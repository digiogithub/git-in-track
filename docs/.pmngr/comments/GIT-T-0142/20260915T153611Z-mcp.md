Scope split for this wave: `internal/config` is owned by another agent, which adds the `search.pando` stanza (`mcpUrl`, `mcpToken`, `restUrl`, `restToken`, `projectId`, `corpusDir`, `allowRemote`). What landed here is the half that belongs to the client: `pando.Options` and its validation in `pando.New`.

Landed in `internal/pando/client.go`:
- `Options{MCPURL, Token, RESTURL, RESTToken, ProjectID string; Timeout time.Duration; AllowRemote bool}`.
- `New` validates both URLs with `checkEndpoint`: scheme must be http/https, host must be present, and **the host must be a loopback address unless `AllowRemote` is set**. Nothing else in the package can override that refusal. An empty URL is valid and means "feature off" (`ErrNotConfigured` at call time), not an error at construction.
- `isLoopbackHost` accepts `localhost` and any IP literal that `net.IP.IsLoopback` accepts (127.0.0.0/8, ::1). A name that is not an IP literal and is not `localhost` is refused rather than resolved, so the guard never depends on DNS the remote operator controls.
- `SanitizeProjectID` is exported here so the config package can derive the default `projectId` without duplicating Pando's rule (`/www/git-in-track` -> `www_git-in-track`); it is a byte-for-byte port of Pando's `sanitizeProjectID` (`internal/llm/tools/remembrances_code.go:1523-1557`) and is covered by a table test over eight paths including a Windows path and a path that sanitises to the empty string.

Tests (`internal/pando/client_test.go`): `TestNewRefusesNonLoopbackURL` (host name, public IPv4, public IPv6, and the REST URL), `TestNewAcceptsLoopbackURLs`, `TestNewAllowRemoteIsTheOnlyOverride`, `TestNewRejectsBadURLs`, `TestNewDefaultsTimeout`, `TestSanitizeProjectID`. `ErrRemoteRefused` unwraps to `ErrInvalidOptions`, so a caller can test for either.

Reviewer: check that `isLoopbackHost` is the whole guard and that nothing reachable from `New` can bypass it.
