Partially done.

**Landed:** the ADR amendment. `docs/adr/ADR-034` carries a section "Amendment — a closed sprint freezes exactly one snapshot" that cites ADR-017, explains why the reasoning inverts at the close (the items leave the scope, so the numbers stop being recomputable from the current state), lists the three rules that keep it from becoming the thing ADR-017 rejected (written exactly once, never for an open sprint, honest about its provenance), and argues the distinction — a series written once at the moment the truth becomes unreachable is closer to a retro than to a cache. Its negative consequences are in the ADR's Consequences section: a stored figure that can disagree with a later reading of history, and a file that grows by one point per sprint day.

The canonical emitted shape, for the §8.2 example:

```yaml
snapshot:
  version: 1
  closed_at: 2026-03-06T23:00:00Z
  totals:
    items: 2
    resolved: 2
    done: 1
    unresolved: 0
    points: 8
    committed_points: 8
    done_points: 3
  by_status:
    done: 1
    todo: 1
  by_assignee:
    alice: { total: 2, done: 1, points: 8 }
  by_label:
    core: { total: 1, done: 1, points: 3 }
  burndown:
    - { date: 2026-03-02, remaining: 2, remaining_points: 8, ideal: 8, completed: 0, unknown: 0 }
  provenance:
    source: git
    approximate: false
    from: 2026-02-25
    commits: 12
    items: 2
    covered: 2
    note: Reconstructed from the git history of the item files.
```

The block sits between `retro` and `created` in the key order. Unmodelled keys inside it are preserved and emitted sorted after `provenance`.
