Core half landed; the `internal/vault` dispatch and `internal/server/metrics.go` are outside the files I was assigned.

The read-side seam is `core.SprintMetricsFromSnapshot(s *core.Sprint, summary core.SprintSummary) (core.SprintMetricsView, bool)`:

- returns `false` for a sprint with no snapshot — that is the signal to fall through to `BuildSprintMetrics` and the `HistorySource`, so an open sprint behaves exactly as before;
- returns a full `SprintMetricsView` otherwise, rebuilt from the stored block, touching no history at all — call it **before** gathering history so the fake-that-fails-if-called assertion holds;
- sets `Provenance.Source = core.MetricsSourceSnapshot` and a note beginning "Read from the sprint's stored snapshot: these numbers were frozen when the sprint was closed on <ts>, not reconstructed now.", appending the provenance of the history that was frozen. That is what distinguishes frozen from live in the UI.

It repairs nothing and recomputes nothing. `TestSnapshotAndLiveMetricsAgree` in `internal/core/sprintsnapshot_test.go` pins that the frozen series equals the live one point for point for the metrics fixture.

The cumulative flow diagram is **not** frozen (the story's snapshot shape does not include it), so `SprintMetricsFromSnapshot` returns an empty `Flow` and `Stats`. The server should either omit those panels for a snapshot-backed answer or say they are unavailable — worth a decision before wiring.
