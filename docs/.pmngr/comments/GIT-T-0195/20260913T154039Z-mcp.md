Left `todo`: `cmd/gintrack` is owned by another agent this wave.

`gintrack youtrack push-comments <item>` dispatches one core method, `youtrack.comment.push`, with `{project, itemId, commentPath, all}`. It answers:

```jsonc
{"project":"ACME","itemId":"ACME-US-0043","jobId":"job_7f2a",
 "pushed":[{"commentPath":"…"}],
 "skipped":[{"commentPath":"…","youtrackCommentId":"3-118","url":"…","reason":"…"}],
 "failed":[{"commentPath":"…","error":"…"}]}
```

Notes for the command:

- `--all` and `--comment <path>` map to `all` and `commentPath`; give one or the other. The vault already refuses neither-or-both with a field-level `invalid_request`, so the command only renders it.
- `pushed` means **queued**, not delivered: without `--wait`, print `jobId` and stop. With `--wait`, follow the job through the sync-jobs API and print the table of comment, remote id and result.
- An item with no YouTrack `external` reference fails with `invalid_request` and a message saying to import or link it first. It is non-retryable; map it to the usage/precondition exit code from `cmd/gintrack/exit.go`, not to a generic failure.
- Extend the existing `youtrack` parent command in `cmd/gintrack/youtrack.go`; do not create a second one.

The MCP equivalent that landed is `push_comment_to_youtrack` in `internal/mcp/tools_youtrack.go`; it is worth reading for the argument validation the command should mirror.
