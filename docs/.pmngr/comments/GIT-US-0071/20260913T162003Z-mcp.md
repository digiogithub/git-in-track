GIT-T-0083 and GIT-T-0088 are done; GIT-T-0092 stays `todo` (only its `docs/08` half was in scope, and it was already satisfied — see the comment there). The guarantee now has tests: `internal/core/triageexclusion_test.go` and `internal/vault/inboxaccept_test.go`. No core behaviour was changed — the exclusion in `walkCards` and the `Filter.Inbox` default hold on every planning surface, including the two cases a reader would not guess: a board column that names the `triage` status (or declares the `triage` category) still renders empty, and 100 triage items of 13 points each, all named by a hand-edited sprint file, move no burndown point.

**One acceptance criterion is deliberately left unticked on GIT-T-0083: `Index.Search` does not exclude triage items, and the suite pins that it does not.** `Index.Search` takes no `Filter`, so hiding triage there would make an inbox item unfindable by text from every surface at once — the quick switcher and the MCP `search_items` tool included — which contradicts ADR-033 ("an item is real from the moment of submission") and this story's own second criterion that a triage item stays readable. ADR-033's Decision scopes the unconditional exclusion to board views, sprint views, sprint candidates and sprint metrics, and scopes queries to a *default* a caller lifts with `Filter.Inbox`; it never mentions search. A search hit carries no estimate, no category and no column, so nothing reaches a planning number through it. `TestSearchStillFindsATriageItem` documents that and will fail loudly if it changes.

If the team wants search to hide the inbox after all, that is an ADR-033 amendment plus an `Index.Search` signature change reaching `internal/vault`, `internal/mcp` and `internal/server` — a story, not a drive-by.
