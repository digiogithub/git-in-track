Criterion 1 reworded on the maintainer's decision (2026-09-15), not satisfied by new code.

It named seven surfaces; the implementation covers five unconditionally and deliberately leaves `Index.Search` out. `Index.Search` takes no `Filter`, so an exclusion there would be unconditional for every caller at once — the quick switcher and the MCP `search_items` tool included — which contradicts ADR-033 ("an item is real from the moment of submission") and this story's own readability criterion. The behaviour, `TestSearchStillFindsATriageItem` and `docs/07-cli-and-api.md` §5.5 all already agreed with each other; only the criterion did not.

The criterion now names the five scoped surfaces, and the search exception is its own ticked criterion with the reasoning in a "Why search is not on the exclusion list" section. No behaviour, test or doc changed.

Verified before closing: `go test ./internal/core/ -run 'Triage|Inbox|Search|Burndown|Sprint'` and `go test ./internal/vault/ -run Inbox` both pass; `internal/core/triageexclusion_test.go` holds 7 tests including `TestSearchStillFindsATriageItem`.

Amending ADR-033 to cover search remains possible as a future story; it would need an `Index.Search` signature change reaching `internal/vault`, `internal/mcp` and `internal/server`.
