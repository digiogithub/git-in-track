All three tasks are done and six of the seven criteria are ticked against what I read, not what I assumed. **Left at `in_review` rather than `done` on purpose**, because the first criterion cannot honestly be ticked and a human should decide what to do about it.

The criterion names seven surfaces, search among them. Six are proven identical with and without triage items present (`internal/core/triageexclusion_test.go`, one shared fixture built twice, a table asking each surface the same question over both worlds). The seventh, `Index.Search`, deliberately does **not** exclude them, and the suite pins that it does not. `Index.Search` takes no `Filter`, so excluding there would make a submission unfindable by text everywhere at once — the quick switcher and the MCP `search_items` tool included — which contradicts ADR-033's rule that an item is real from the moment of submission and GIT-T-0088's criterion that it stays readable. ADR-033's Decision scopes the unconditional exclusion to board views, sprint views, sprint candidates and sprint metrics and scopes queries to a liftable default; it says nothing about search. Nothing reaches a planning number through a search hit, which carries no estimate, no status category and no column.

So the criterion is wrong as written rather than unfinished. Two ways to resolve it, both a human's call: reword the criterion to name the six surfaces and the deliberate exception, or change ADR-033 first and then the behaviour. Ticking it as it stands would record something false.

What this pass added: `docs/07-cli-and-api.md` §5.5 now writes the exclusion's scope down in prose — what is excluded unconditionally, what is excluded by default, and why search is neither — so the reasoning is no longer only in a test comment. `CHANGELOG.md` gained the explicit "a project created before this change has no triage status and therefore no inbox" note the sixth criterion asks for. Verified with `go build ./...`, `go test -race ./...`, `gofmt -l internal cmd`, the web suite, and `make lint` at zero issues.
