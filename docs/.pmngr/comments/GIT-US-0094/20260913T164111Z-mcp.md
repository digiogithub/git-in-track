`gintrack youtrack kb push|pull <path>` landed with `--recursive`, `--wait` and `--json`, plus a third subcommand `kb status [path]` that keeps `--remote` behind an explicit flag because it is one article read per page. `docs/07` §4.15 documents all three.

The thing to review carefully is the exit contract, because CI will depend on it: `--wait` gives a **conflict** exit 5 and a **failed job** exit 1, deliberately different codes for different responses. A conflict is not an error — the page is untouched and `<page>.conflict.md` holds the other side — but it must not read as success either. The command re-reads `youtrack.kb.status` after the job rather than trusting the queueing answer, and `--json` prints a declared payload with `ok`, `state`, `conflicts` and the per-page states.
