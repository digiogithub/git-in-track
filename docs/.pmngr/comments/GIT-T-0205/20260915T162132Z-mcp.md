Card landed on `feat/phase-9-agent-and-search` (wave 3).

`web/src/features/settings/PandoSearchCard.tsx`, mounted in `SettingsPage.tsx` between `McpToolsCard` and `YouTrackCard`, gated on the new `Capabilities.searchSettings` (true in companion mode, false in browser-only mode) the way `YouTrackCard` is gated on `youtrackSupported` — the card has to exist before anything is configured.

It renders: the backend badge (`core`/`pando`, plus a `degraded` badge when the live probe failed), the MCP and REST URLs, the code project id, the corpus directory, an `allowRemote` switch with docs/07 §3.3's warning quoted, the reachability result with its error text, a per-repository corpus table (repo, dir, last export, documents, written/removed/skipped) with a documents/last-export summary, **Reindex now** with live progress from the `search.progress` frames (phases export → code → kb → completed/failed, button disabled while a job runs, settings re-read on a terminal frame so the finished job's counts, `kbNote` and per-repository errors are what is shown), the last job with its `kb` counts, and the standing embedding-model warning ("per Pando instance, not per corpus"). There is **no token field**: a note says both tokens are set in the configuration file or in `GINTRACK_PANDO_MCP_TOKEN` / `GINTRACK_PANDO_REST_TOKEN`. Problem codes map to their own sentences — `search_reindex_running` reads as "a reindex is already running, it was left alone", `search_not_configured` as "there is nothing to index yet".

Provider seam (`web/src/api/provider.ts`): `getSearchSettings(): Promise<SearchSettings>`, `updateSearchSettings(patch: SearchSettingsPatch): Promise<SearchSettings>`, `reindexSearch(): Promise<SearchReindexJob>`; types `SearchSettings`, `SearchSettingsPatch`, `SearchCorpus`, `SearchCorpusStats`, `SearchReindexJob`, `SearchReindexRepo`, `SearchReindexKbStats`, `SearchReindexPhase`; error codes `search_reindex_running` / `search_not_configured`; capability `searchSettings`; `ChangeEvent` variant `{kind:'searchProgress', operationId, repoId, phase, percent, done, total, message}`. Implemented in `companion-provider.ts` (`toSearchSettings`/`toSearchReindexJob`, `search.progress` added to the subscribed topics), refused with `not_supported` in `browser-provider.ts`, scripted in `fake-provider.ts` (`FakeSearch.settings|persisted|reindexError|reindexJob`, plus `finishSearchReindex()` for the job a test wants read back).
