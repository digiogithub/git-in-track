Left `todo` on purpose: `internal/server/` belongs to another agent this wave, so the HTTP half was not written here. The vault half is on the branch and ready to call.

`POST /api/v1/sprints/{id}/close` → `s.call(ctx, "sprint.close", params)`, now accepting two extra fields on top of what it already sends:
`{team, id, rev, carry[], transfer: {mode, target?}, dryRun}`.
`mode` is `next|backlog|none`; absent or `none` expands to nothing, which is exactly today's behaviour, so an existing caller is unaffected. `carry` entries override the bulk mode for the references they name.

`POST /api/v1/sprints/{id}/transfer` → `s.call(ctx, "sprint.transfer", params)` with:
`{team, id, rev, mode, target, carry[], dryRun}`. `mode` defaults to `next`. It closes nothing and never edits the source sprint: `items` and `committed` come back untouched.

Both answer `vault.SprintResult`, which gained one field: `dryRun bool`. **A dry run returns an empty `writes` and must publish nothing** — no `sprint.changed`, no `item.changed`, no commit-on-save. Gate `publishWriteSets` on `!result.DryRun` rather than on `len(writes) == 0`, so the intent is visible in the code.

`writes` is now merged to one `RepoWriteSet` per repository (`mergeRepoWrites`), so a bulk transfer of ten items into one sprint arrives as one entry for the team repository plus one per project clone, not one per item.

Error codes to map: `sprint_target_completed` (the target sprint is over; 409 reads better than 422), `stale_revision` → 412, `not_found` for an unknown sprint or a `next` with no sprint to move into, `invalid_request` for an unknown mode. A **per-item** failure is not an error: it comes back on its own `report.carried[].error` line with a 200, and `repo_not_cloned` for a backlog return is the common one (R-SPR-8).
