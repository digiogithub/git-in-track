Landed as `web/src/features/agent/store.ts` (not `agent-store.ts`; the folder already namespaces it). `useAgentStore` is the app singleton, `createAgentStore()` builds an independent one so tests never reset a singleton.

State: `provider`, `repo`, `threadId`, `knownThreadIds`, `threads`, `messages` (`AgentMessage[]`), `stateDoc` (`PandoState | undefined`), `runStatus`, `interrupt`, `error`, `readOnly`, plus the live `thread`/`guard`/`controller`. Actions: `attach`, `newThread`, `selectThread`, `send`, `resume`, `cancel`, `reattach`, `refreshThreads`, `deleteThread`, `dispose`.

Per `app/store.ts`, conversation state only: no navigational state, and the only server read here is the thread list, which is part of restoring identity rather than rendered server data.

- Each `send` reuses the thread id and takes a fresh run id (the SDK allocates it) and resends the whole transcript.
- `runStatus` is decided in `drive()`, not by the reducer: `idle` → `running` → `idle` | `interrupted` | `error` | `cancelled`. `RUN_ERROR` and a mid-stream transport failure are both terminal and both keep whatever text had arrived.
- `cancel()` aborts the controller *and* calls `cancelAgentRun`, because aborting the fetch only drops our end of the stream while the run keeps the thread busy.
- Thread ids persist in `localStorage` under `gintrack:agent-threads:<repo>` and `gintrack:agent-active-thread:<repo>`, so a reload keeps the conversation's identity; every access is try/caught for private modes.
- `ThreadGuard` is the one-thread-per-tab rule, over `BroadcastChannel`: a tab announces the thread it wants, the owner answers, the newcomer goes `readOnly` and `send`/`resume` refuse with `session_busy` rather than racing. It is advisory — a tab that hears nothing takes ownership, which fails in the right direction. `channelFactory`/`wait`/`tabId` are injectable, so the tests are deterministic and need no real channel.
- `reattach()` is already shaped for PANDO-EP-0003: hydrate from `/threads/{id}/messages`, then stream `/threads/{id}/stream`. Nothing here has to be rewritten when park-on-disconnect lands; the guard just gets deleted.

Tests: `store.test.ts` (20) against `FakeProvider` — stable thread id with fresh run ids, growing transcript, persistence across a simulated reload, cancel, thread switching, `refreshThreads`/`deleteThread`, error propagation, and both halves of the tab guard.
