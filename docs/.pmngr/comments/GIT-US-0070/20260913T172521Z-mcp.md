Closed after writing the one thing that was missing: the journal's documentation. The other seven criteria were verified against `internal/syncengine/journal.go` and `engine.go` rather than assumed — `JournalName = "jobs.json"` joined to `Options.CacheDir`, the atomic tmp-plus-rename write behind a `DefaultJournalFlush` of 500 ms, `DefaultRetention` of 7 days, `moveAside` for a corrupt or unknown-version file, and `replay` re-queuing a `running` job with its attempt count intact.

`docs/07-cli-and-api.md` §4.1 now carries `##### The journal (GIT-US-0070)`: location, atomic write and coalescing window, a worked example of the whole JSON document, the `version` field and the move-aside behaviour, the retention window, the delete-safety statement, and the idempotence contract in its own paragraph with the reason attached.

**One correction a reviewer should know about.** The previous `CHANGELOG.md` entry said the journal holds "ids, kinds, keys, attempt counts, states and redacted errors, never item content and never a credential". The first half was incomplete: `journalDoc.Jobs` is `[]Job`, and `Job.Payload` is persisted — it has to be, because replaying a job means running it with the arguments it was given. What is genuinely absent is item content and any credential: a token is read at dispatch time from the `0600` machine configuration (ADR-032) and error messages are redacted before being recorded. Both the docs and the CHANGELOG now say that accurately instead of implying the payload is dropped.

Verified with `go build ./...`, `go test -race ./...`, `gofmt -l internal cmd` and `make lint` — all clean, zero issues.
