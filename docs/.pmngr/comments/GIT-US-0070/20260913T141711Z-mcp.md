Code complete and left `in_review`, not `done`: seven of the eight acceptance criteria are met and tested, and the eighth is the `docs/07-cli-and-api.md` pass (GIT-T-0125), which this wave could not take — it owned `internal/syncengine/` only, and the docs were being edited by another agent in the same working tree. GIT-T-0125 keeps a comment with the location, the exact JSON shape, the permissions, the retention rule, the delete-safety statement and the idempotence contract, all written from the code that landed, so the docs pass is a transcription rather than a re-investigation.

What landed: `journal.go` writes `<CacheDir>/jobs.json` (0600 in a 0700 directory) as `jobs.json.tmp` plus a rename, coalesced behind a timer on the engine clock so a burst of transitions is one write and no worker ever blocks on disk. `Engine.Start` replays it — queued jobs return to the queue, a job recorded as `running` is re-queued with its attempt count intact, `done` and `cancelled` entries older than the retention window are dropped on the way in — and a corrupt, truncated or unknown-version file is renamed to `jobs.json.corrupt-<UTC>`/`.version-<UTC>` and the engine starts empty. Pruning also runs hourly on the clock; failed and dead-lettered jobs are never swept. Payloads and error strings are redacted before anything reaches the disk, asserted by a test that plants a permanent token in a payload, in a nested object and in a URL.
