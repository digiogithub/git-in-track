Landed in `internal/server/search_pando.go` (native only). `pandoSearcher` calls `SearchKB` through a small `pandoAPI` interface that `*pando.Client` satisfies — that interface is what lets the tests drive every path with no live MCP server. `parseCorpusPath` reads `<PROJECT>/items/<ID>.md` and `<PROJECT>/kb/<path>.md` back into their parts, scanning from the right so a Pando that reports the path with a prefix still resolves; an item must be exactly one file deep. Items resolve through `vault.Vault.Item`, pages through the new `vault.Vault.PageByProjectPath`. Unresolvable, deleted and non-layout candidates are dropped and counted for one debug line. Each hit carries Pando's score, the matched chunk as a one-line snippet and `Source: "pando"`. Tests: `TestParseCorpusPath` (7 cases) and the drop/dedup assertions of `TestSearchMergesSemanticHitsAfterExactOnes`; the empty-result case is `TestSearchOverFetchesAndScopesByPathPrefix`, whose fake returns nothing.
