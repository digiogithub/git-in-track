Two findings worth carrying forward:
1. **Pando's tool results are TOON, not JSON.** `NewStructuredResponse` renders through `toon-go`. A decoder for the emitted subset lives in `toon.go` (no new dependency). Anyone who assumed `json.Unmarshal` on tool text would have shipped a client that never parses anything.
2. `kb_search_documents` gained `path_prefix` on 2026-09-14 (`remembrances_kb.go:274-279`) and it is applied in SQL on both search legs, so it is the right way to scope a search to the exported corpus. `SearchKB` sends it.
