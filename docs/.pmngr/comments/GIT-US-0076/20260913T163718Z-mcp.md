Landed the web half: `pushCommentToYoutrack` on all four providers (browser-only fails loudly), `comment-sync.ts` deriving pending/sent/failed from the comment's `external` entry plus `sync.job.*` frames, the per-comment action and badge in `CommentsPanel`, the "send after saving" checkbox in `FeedbackPanel`, and `push_comments` in the YouTrack settings card. 152 tests pass across `features/{backlog,feedback,settings}`.

One criterion is deliberately left unticked on GIT-T-0188: `docs/05-web-app.md` and `CHANGELOG.md` were **not** updated. This wave scoped the web agent to `web/` because other agents were editing `docs/` in the same working tree, so writing there would have raced them. The documentation half needs a follow-up by whoever owns those files.

Two things a reviewer should know. First, `external` always beats a job frame, so a re-delivered `failed` cannot un-send a comment that already reached the issue — the engine delivers at least once, so this is a real case, not a theoretical one. Second, there is no delete-remotely action and a test asserts its absence: deletion stays local, because a repository is not the authority on an issue's conversation.

The companion provider calls `POST /api/v1/youtrack/comments/push`, which **does not exist on the server yet** — the vault operation `youtrack.comment.push` and the job kind do. That route is the one remaining gap between this UI and a working push.
