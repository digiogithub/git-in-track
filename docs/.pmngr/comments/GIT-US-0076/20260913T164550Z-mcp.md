`POST /api/v1/youtrack/comments/push` landed in `internal/server/youtrackcommentsapi.go` — the last gap between the web action and the job that does the work. It is as thin as the import route beside it: resolve the project from `?key=`, refuse a project with no usable connection *before* anything is queued with the same five `youtrack_*` codes, hand the call to `youtrack.comment.push` and answer `202` with the job id and the pushed/skipped/failed lists. The path and the body match what the web client already calls.

Two things a reviewer should check. The coalescing key is the **comment path**, not the item id, and `TestCommentPushRouteCoalescesOnTheCommentPath` pins it: two pushes of one comment are one job, a second comment of the same item is its own. And `pushed` means *queued* — the evidence a reader trusts is the comment's own `external` entry, which the job writes back through `comment.update`.

`docs/07` §5.5 documents the route, the three rules and the non-retroactive meaning of `push_comments: auto`; `CHANGELOG.md` records both. `docs/05-web-app.md` is still owed the UI half of GIT-T-0188 — it belongs to neither the web agent nor this one.
