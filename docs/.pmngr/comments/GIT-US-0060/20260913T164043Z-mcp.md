Landed `/p/$project/inbox` as a two-pane triage queue: infinite list with URL-held `pending|snoozed|all` filters, detail pane through the sanitised `ItemBody`, accept/reject/snooze/duplicate with optimistic rollback, `j`/`k`/`a`/`r`/`s`, and a sidebar entry with a pending badge — both hidden for a project with no `triage` status. 41 new tests; the full web suite is 888 green with lint, tsc, tokens and build clean.

Two things a reviewer should know. The accept form is `InboxAcceptPage.tsx`, a wrapper that composes the *same* pieces as `ItemEditorPage` (`FrontMatterForm`, `MarkdownEditor`, `DiagnosticList`, `ConflictDialog`, `readProjectSchema`/`buildPatch`) rather than the page itself, because `ItemEditorPage` takes no props and this wave did not own `features/editor/`. The clean follow-up is a `mode: 'edit' | 'accept'` prop on `ItemEditorPage` and deleting the wrapper. Its save is two calls under one button — `triageInboxItem` first, since it owns status and parent and is the write that commits the acceptance, then `updateItem` pinned to the rev the triage returned.

There is deliberately no type picker on accept: an item id encodes its type for life, so `InboxTriageInput` carries no `type` field at all and "this should have been an epic" is answered by creating the right item and marking this one a duplicate.

`web/src/test/router.tsx` has no `/p/$project/inbox` route, so the sidebar entry is covered by its own tree instead of through `AppShell.test.tsx`; adding it there is a one-liner for whoever owns that harness.
