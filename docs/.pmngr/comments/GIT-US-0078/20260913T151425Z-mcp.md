Landed in `internal/server/syncjobs.go` (new) plus the settings half folded into `internal/server/sync.go`: six routes under the existing `/sync` mount, three new problem codes in `problem.go`, and `docs/07-cli-and-api.md` §5.5 "Background jobs and the engine settings".

Two things a reviewer must know. **`persisted` is always `false` for the engine half** — `internal/config` has no `sync.engine` section to save into, so `syncState.persist` writes nothing; the reload-mutate-save seam is there for whoever adds it (GIT-T-0175). And **retrying a cancelled job creates a new job id**: the engine's state machine has no edge out of `cancelled`, so the handler re-enqueues the same kind, key and payload and the answer names the new id — documented, not a bug.
