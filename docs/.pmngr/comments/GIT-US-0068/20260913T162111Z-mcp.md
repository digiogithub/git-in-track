The two seams GIT-T-0158 left open are closed. GIT-T-0224 adds the vault method, GIT-T-0225 the client call. Neither touched `internal/server`; both are for its owner to pick up.

**1. `internal/server` can now delete `writeCommentExternal` (and its hand-rolled reindex).** Replace it with one dispatch, exactly as every other vault write is made:

```go
var out struct {
    Comment core.Comment   `json:"comment"`
    Writes  vault.WriteSet `json:"writes"`
}
err := dispatchVault(ctx, m, "comment.update", map[string]any{
    "id":          params.ItemID,      // routes to the right repository; also cross-checked
    "path":        params.CommentPath, // vault-relative
    "rev":         string(rev),        // the rev of the bytes the push was built from; "*" is the If-Match wildcard
    "setExternal": []core.External{ref},
}, &out)
```

It refuses a stale rev with `stale_revision` carrying `currentRev` (still retryable, which is what a comment edited mid-flight wants), writes through the tracking file system, and **folds the index forward in the same commit** — so the `m.reindex` call and the `s.log.Warn` around it go away too. `out.Writes` is the `WriteSet` to hand `commitJobWrites`, rather than rebuilding a one-file set by hand.

`setExternal` upserts by *system*, which is exactly the semantics of the local `upsertExternal` helper, so that can go as well. `body` is a separate optional field: the push does not pass it, so the comment text and its `updated` stamp are untouched — recording a remote id is bookkeeping, not an edit a reader should see stamped.

**2. `editRemoteComment` can stop probing.** `*youtrack.Client` now has `UpdateComment(ctx, issueID, commentID, text) (Comment, error)`, so the `youtrackCommentEditor` interface assertion and its terminal "this build cannot edit a remote comment" branch are dead. It posts to `/api/issues/{id}/comments/{commentID}` — the same verb as a create, the id in the path being the whole difference — so a retried delivery is an edit and never a second comment.

Note `go build ./internal/server/...` is currently red on another agent's in-flight change (`internal/server/youtrackjobs.go:243`, `link.FieldMap.Names` against a `map[string]string`). Not from this wave.
