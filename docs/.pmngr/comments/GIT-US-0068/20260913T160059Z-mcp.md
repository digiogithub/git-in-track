Landed as `internal/server/youtrackcomments.go`: the `youtrack.comment.push` kind, the create-then-edit decision, the rev-guarded write-back and the per-project attribution template (`integrations.youtrack.comment_template`, new on `config.YouTrackLink`). Left **in review, not done**, for two reasons a reviewer has to weigh.

**One: the write-back does not go through the vault, because no vault method rewrites a comment's front matter.** `comment.add` appends and nothing updates, and `internal/core`/`internal/vault` were another agent's this wave, so `writeCommentExternal` does the file-level equivalent AGENTS.md documents — read, hash, parse, upsert, re-read and compare the hash immediately before writing — then rebuilds the index and tells commit-on-save. It is the only place in `internal/server` that writes a repository file directly, and a `comment.update` vault method would replace it whole.

**Two: the edit path cannot reach a real instance.** `*youtrack.Client` has `AddComment` and no `UpdateComment`, so the handler probes an optional `youtrackCommentEditor` interface: a client that grows `UpdateComment(ctx, issueID, commentID, text)` satisfies it with no change here, and a client that has not fails the second push terminally rather than posting a duplicate. That method is the one thing this story still needs from `internal/youtrack`. `docs/03-data-model.md` §11, the §18 schema and ADR-031 (GIT-T-0150) are also still open, and are why the first and last criteria stay unticked.
