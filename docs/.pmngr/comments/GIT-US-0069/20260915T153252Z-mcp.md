**Two corrections to the plan, both found by reading Pando's source and confirmed live.**

1. The tool glob is `gintrack_*`, not `gintrack__*`: Pando names a gateway tool `<server>_<tool>` with one underscore (`internal/llm/agent/mcp-tools.go:75`).
2. `[AGUI] FrontendTools` must be written explicitly. Its documented default is `true`, but that only applies while the key is absent from every config file; an `[AGUI]` section without it decodes to `false`, and the first live run reported `"frontendTools": false`.

**Acceptance criteria not met, and why.**

- *"No token value is written into any file inside the repository."* Not achievable as written. Pando does not expand environment variables inside an MCP server's `Headers`, and `.pando.toml` must live in the `agui-serve --cwd`. The companion bearer token is therefore literal in `[MCPServers.gintrack.Headers]`, mitigated by mode 0600, a SECURITY banner in the file, a stdout warning and tests keeping it out of every other generated file. Recorded as a negative consequence in ADR-035 and in docs/20 section 6.
- *"`docs/07-cli-and-api.md` gains the `gintrack agent init` command and `CHANGELOG.md` records the feature."* Both files, and the root `README.md` link that GIT-T-0110 asks for, are outside this agent's file ownership for this wave. The exact patches are in the hand-off report for the coordinator to apply; until they land this story is not complete.

Also worth a reviewer's eye: the `KBPath` this command generates is `<cacheDir>/pando-kb/<repo id>`, while GIT-US-0073 describes the exporter's root as `<CacheDir>/pando-kb/<project>/`. If the exporter keys by project key rather than repository id the two will not meet and semantic search will silently find nothing. One of the two has to move; the command has a `--repo` but no `--kb-path` override today.
