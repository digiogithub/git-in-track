Landed: `cmd/gintrack/youtrack.go` with `connect` and `status`, documented in `docs/07-cli-and-api.md` §4.15 with flags, precedence and exit codes. `connect` resolves the token from `--token`, then `$GINTRACK_YOUTRACK_TOKEN`, then a piped stdin, probes with `Me` **and** `Project` — so a token that authenticates but cannot see the named project fails before anything is written — and only then writes `project.yaml` surgically and the `0600` configuration. Tests assert the precedence, that a 401, 403 or 404 leaves both files byte-identical, and that neither the text nor the `--json` output contains the credential.

Two notes for the reviewer. `connect` stores the token whichever of the three sources it came from, on the reading that connecting is the act of making the link permanent; the payload reports `tokenInput` (`flag` | `env` | `stdin`) beside `tokenSource` (`file`) so a script can still see where it came from. And `go test -race ./cmd/...` has one failure that is not this story's: `TestMCPOverStdio` expects 13 MCP tools while another agent's in-flight `internal/mcp` change now advertises 18. `go test -race ./cmd/... -run TestYouTrack` is green, and `make lint` reports 0 issues.
