Landed in `internal/pandosync/paths.go` and the writer half of `exporter.go`, tests in `exporter_test.go`.

- Atomic write: bytes go to a sibling `.<name>.md.tmp` dot file and are renamed into place. The temp name deliberately does **not** end in `.md`, so an importer walking the corpus in the window before the rename cannot pick it up. A leftover temp from a crash is pruned by the next full export.
- Path guarding: `itemPath` validates the id against `core.ItemID.Valid()` and derives the project from it; `pagePath` runs the lexical check `internal/mcp/paths.go` runs on a tool argument (empty, NUL, backslash, absolute, Windows volume, any `..` segment) and then re-confines the assembled path under `<project>/items` or `<project>/kb`. A refusal is `*ErrForbiddenPath`; it skips that document and logs, it does not fail the export.
- Deletion unlinks the file and walks up removing directories it emptied.

One deviation from the task body: the corpus root comes from `Options.Dir` (or `Options.FS`), not from `config.Config.CacheDir` — `internal/pandosync` must not import `internal/config`, so resolving the cache dir is the caller's job in wave 2. `New` refuses a corpus root that is a git working tree, so the corpus can never be written inside a repository.

Reviewer: `TestWritesAreAtomic` (asserts the exact op sequence write-temp → rename via a spy FS), `TestExportAllRefusesPathsThatEscapeTheCorpus`, `TestPagePathRefusals`, `TestExportAllPrunesVanishedSourcesAndEmptyDirectories`, `TestExportAllPrunesLeftoverTemporaryFiles`.
