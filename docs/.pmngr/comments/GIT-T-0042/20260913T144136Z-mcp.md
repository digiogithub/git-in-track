Left `todo` on purpose: `internal/server/` belongs to another agent this wave, so the HTTP half of the inbox was not written here. The vault half it needs is on the branch and ready to call.

`GET /api/v1/inbox` → `s.call(ctx, "inbox.list", params)` with:
`{project, status[], type[], label[], assignee, text, sort, order, limit, cursor, fields}`.
`status` is the **triage** state (`pending|accepted|rejected|snoozed|duplicate`), not a workflow status; an unknown value is refused with `invalid_request`. The vault sets `Filter.Inbox = only` and `Filter.SnoozeAsOf = v.Now()` itself, so no caller can forget the clock and silently expire nothing.

The answer is `vault.InboxPage`: `{items, nextCursor, total, counts, pending}`. `counts` is per triage state **across the whole queue**, not the page, and `pending` already counts an expired snooze as pending again — that is the `pendingCount` the `inbox.changed` event needs, with no second call.

`POST /api/v1/items/{id}/triage` → `s.call(ctx, "inbox.triage", params)` with:
`{id, rev, action, status?, parent?, snoozedUntil?, duplicateOf?}`, where `rev` comes from `requireIfMatch`. Pass the empty string for the `If-Match: *` wildcard: the vault treats an empty rev as unconditional, exactly as `item.update` does. `action` is `accept|reject|snooze|duplicate`.

The answer is `vault.InboxTriageResult`: `{item, action, pending, writes}`. `writes` is one ordinary `WriteSet` — a duplicate decision carries two files in it, the entry and the link target — so `publishWrite` needs nothing special. `pending` is the count for the `inbox.changed` payload.

Error codes to map: `no_triage_status` (the project declares no triage status, so it has no inbox — a 409 or 422 rather than a 500), `stale_revision` → 412, `not_found` for an unknown item or duplicate target, `invalid_request` for everything else.
