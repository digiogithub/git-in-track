Landed in `internal/server/search_settings.go`. GET answers the seven fields the task asks for (Pando URL, corpus dir, project id, last export time, document count, a live reachability probe and the selected backend) plus per-repository corpus stats and the running/last reindex. PATCH follows `gitState.persist` exactly — reload the file, replace the section, save, return `persisted` — and applies to the running process first, rebuilding the Pando client, the semantic backend and every exporter. Only the non-secret fields are written, so an env-resolved token cannot be copied into the file, and no token is patchable or reported. No `ConfigPath` → applied to the process only, `persisted: false`. Invalid values (non-loopback URL without allowRemote, unparseable URL, relative corpusDir) are `invalid_request` 400 with nothing adopted. Tests: `TestSearchSettingsReportsTheCorpusAndTheBackend`, `TestSearchSettingsPatchPersists` (round trip against a real config file), `TestSearchSettingsPatchWithoutAConfigFile`, `TestSearchSettingsPatchRejectsBadValues`.
