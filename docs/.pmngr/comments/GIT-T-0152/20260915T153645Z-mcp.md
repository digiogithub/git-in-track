Landed in `internal/pando/search.go`, `types.go` and `toon.go`.

**The result format is not JSON.** Pando renders every structured tool result through `internal/llm/tools.NewStructuredResponse`, which prefers **TOON** (Token-Oriented Object Notation) and only falls back to TOML and then to indented JSON. Verified against a live Pando: `kb_search_documents` and `code_list_projects` come back as TOON text. `internal/pando/toon.go` is therefore a decoder for the subset of TOON v4.1 that Pando's encoder can emit — object bodies, inline primitive arrays, list form, tabular form with nested field groups, keyed tabular form, comment lines, CRLF — producing the JSON data model so the typed structs are filled by a json round-trip and unknown fields are ignored for free. No new dependency: `toon-go` is not vendored in. Comma is the only delimiter accepted; a header declaring tab or pipe is rejected rather than mis-split.

`code_hybrid_search` is the exception and is handled separately: its text content is compact human-readable lines and the machine-readable page travels in `structuredContent.metadata` as a JSON string (`WithResponseMetadata`, surfaced by Pando's MCP server at `internal/mesnada/server/server.go:644-660`). `SearchCode` parses that, and falls back to decoding the text when it is absent.

Wrappers:
- `SearchKB(ctx, query, KBSearchOptions)` -> `[]KBHit{FilePath, Chunk, Score, Rank, Tags, Metadata, CreatedAt, UpdatedAt, Links, Backlinks}`. Sends `query`, `limit` (clamped to 20), `tags`, `exclude_outdated` (a `*bool`, so Pando's default of true survives when unset), `scope`, `sort_by_date` and **`path_prefix`** — the parameter Pando added on 2026-09-14, verified in `internal/llm/tools/remembrances_kb.go:274-279`; it is the only way to keep a search inside the exported corpus. Unset options are not sent at all, so Pando's own defaults win.
- `SearchCode(ctx, projectID, query, CodeSearchOptions)` -> `[]CodeHit`. `limit` clamped to 50, `offset`, `languages`, `symbol_types`, `min_score`, and `include_docs` **always sent explicitly** because Pando's default of false silently drops every Markdown hit. An empty `projectID` falls back to `Options.ProjectID`.
- `ListProjects(ctx)` -> `[]Project{ProjectID, Name, RootPath, IndexingStatus, LanguageStats, CreatedAt, UpdatedAt, LastIndexedAt}`.
- `IndexProject(ctx, path, name)` -> job id (indexing is asynchronous; the job is still running when this returns).
- `ReindexKB(ctx)` -> `ReindexStats` over `POST {restUrl}/api/v1/remembrances/kb/reindex` with `X-Pando-Token`. `ErrNotConfigured` when `restUrl` is empty, `ErrReindexRunning` on 409, `ErrUnauthorized` on 401/403, `ErrNotConfigured` on 503 (Pando's "mirror not configured").

**An empty result set is not an error.** Pando answers "No documents found matching the query." with a bare sentence rather than an empty array; the client returns `(nil, nil)` for it. A tool that actually failed sets `isError`, which becomes `ErrToolFailed` carrying Pando's own message. A result that is neither becomes `ErrUnreachable`, never a silent empty list.

Tests: recorded payloads captured from a live Pando live in `internal/pando/testdata/*.toon`. `search_test.go` covers parsing (escapes inside quoted chunks, nested `metadata`, tags, links/backlinks, RFC3339 timestamps), the exact parameters sent, limit clamping at both caps, omission of unset options, unknown fields at every level, the empty-result path for all three tools, the tool-error path, and a malformed result. `toon_test.go` covers the decoder directly: scalars, quoted values carrying commas and colons, nested objects, inline arrays, list form, tabular form, nested field groups, keyed tabular form, root arrays, comments, CRLF, delimiter rejection and six malformed inputs. `go test -race ./internal/pando/...` passes.

Reviewer: `toon.go` is the new and least obvious code — `parseListItems` (the hyphen line carries the item's first field one level deeper, §10) and `rowObject` (depth-first leaf assignment for nested field groups) are where a bug would hide.
