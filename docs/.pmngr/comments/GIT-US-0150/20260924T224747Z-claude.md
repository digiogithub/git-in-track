Implemented as groundwork, on purpose. `web/src/cache/verify-cache.ts` persists the document
of the core's `MemVerifyCache` (the browser half of `core.VerifyCache`) as one record per
project in a new `verify-caches` store of the `gintrack-cache` IndexedDB database, the same
database as the index snapshots (ADR-037 §7). `web/src/cache/cache-db.ts` now owns that
database and its upgrade to version 2; a version-1 database keeps its snapshots. The document
is stored as opaque text (the core decodes and merges it), an empty export deletes the record,
and every operation swallows a missing, blocked or failing IndexedDB and reads as empty.

What it enables today: nothing user-visible. Browser-only mode has no test ingest and no
coverage host (`listCoverage`, trace and impact answer `unavailable`), so nothing records into
the store or reads from it, and no `verifycache.*` core method was added for a caller that does
not exist. It is the persistence a future browser-side ingest or coverage reader will use so
evidence recorded in a tab survives a reload. Docs: docs/05 §6, docs/03 §21 note and R-REQ-11b,
CHANGELOG. Tests: `web/src/cache/verify-cache.test.ts` against `fake-indexeddb` (already a dev
dependency).
