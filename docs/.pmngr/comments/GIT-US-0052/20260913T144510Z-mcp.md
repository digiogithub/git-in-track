Landed: `internal/server/youtrack.go` mounts `GET|PATCH /api/v1/youtrack/settings`, `POST /api/v1/youtrack/test`, `GET /api/v1/youtrack/projects?q=` and `GET /api/v1/youtrack/fields?project=` inside the authenticated group, all documented in `docs/07-cli-and-api.md` §5.5 and covered against an `httptest` YouTrack stub whose error bodies echo the credential back, which is what proves the redaction survives into a problem document.

Three things the web wave needs. Every endpoint takes `?key=<gintrackProjectKey>`, optional with one mounted project and a `400 invalid_request` with several. There are five problem codes, not three — `youtrack_not_configured` (409) plus `youtrack_unauthorized`, `youtrack_forbidden`, `youtrack_not_found` and `youtrack_unreachable`, all **502**: answering the upstream's own 401 would tell a browser its session had expired, so the `code` carries the distinction instead. And `tokenSource` has a fourth value, `flag`, for a token the CLI supplied to one process. `PATCH` is sparse with pointer fields so clearing is expressible, `token` is write-only, and a patch that would not load back is refused before `project.yaml` is touched.
