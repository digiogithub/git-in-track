Backend landed on `feat/phase-9-agent-and-search` (wave 2). All five child tasks are in_review.

**What landed**
- `internal/core/search.go`: `Searcher` (one method, the existing `Search(q, limit) []SearchHit`), `SearchSourceCore`/`SearchSourcePando`, and a `var _ Searcher = (*Index)(nil)` assertion. `SearchHit.Source` is set by `Index.Search` for both items and pages. No behaviour change; `GOOS=js GOARCH=wasm go build ./wasm` still builds.
- `internal/vault`: `Vault.Pages()` (cloned, never the index's live pointers), `Item(id)`, `Page(vaultPath)` — together these satisfy `pandosync.Source` and `pandosync.Lookup` — plus `PageByProjectPath(project, rel)` which is the reverse of the corpus layout. New seam `Workspace.SetSemanticSearcher(vault.SemanticSearcher)` and method `search.semantic` on the contract (`Workspace.SearchSemantic(ctx, SemanticQuery)`); `searchHit` is now exported as `vault.SearchHit` with a `source` field.
- `internal/server/search_pando.go`: `pandoSearcher` (satisfies `vault.SemanticSearcher`) over a small `pandoAPI` interface that `*pando.Client` satisfies. Over-fetch `min(limit*2, 20)`, `PathPrefix` `<PROJECT>/` (`/items/` or `/kb/` when the caller filters by kind), 300 ms context budget, `parseCorpusPath` resolving `<PROJECT>/items/<ID>.md` and `<PROJECT>/kb/<path>.md` **from the right**, so a Pando that reports the path with a prefix still resolves. Unresolvable or deleted candidates are dropped and counted.
- `handleSearch` (`internal/server/items.go`) answers `{"query","hits","total","engine","degraded"}`: exact hits first in their existing order, then semantic ones not already present, each tagged `source`. The two score spaces are never sorted together. Any Pando failure returns the core result with `degraded: true` and is logged once per state change (`searchState.noteDegraded`); `ErrNotConfigured` is not a degradation.
- `features.search` is `s.search.backend()`: `"pando"` only while a backend is installed **and** not currently degraded.

**Decisions worth a reviewer's eye**
- The merged list is capped at the caller's `limit`. Exact hits lead, so semantic ones surface exactly when the substring engine under-returns — which is the case the story motivates.
- The chunk-count ceiling of the story is implemented as the latency budget rather than as a configured chunk count: the companion cannot see Pando's chunk count, and a timeout is the same protection measured on the thing that actually matters.
- `PathPrefix` assumes Pando reports corpus-relative paths. If a deployment reports something else, a project-scoped query under-returns (the documented cost); the parse itself is prefix-tolerant.

**Tests** `go test -race ./internal/core/... ./internal/vault/... ./internal/server/...` passes.
