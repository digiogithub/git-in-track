For the shape a saved `field_map` has to hold: the client can now report the *values* of a field, not only its name, so a map from `In Progress` onto a local status is expressible. `internal/youtrack/bundles.go` exposes:

```go
func (c *Client) ProjectFieldValues(ctx context.Context, projectID string) ([]FieldValues, error)
func (c *Client) BundleValues(ctx context.Context, setting CustomFieldSetting) (FieldValues, error)
func SupportedBundleType(bundleType string) bool
```

`FieldValues` carries `Name` (the YouTrack field name), `FieldType` (`"enum[1]"`, `"state[1]"`, `"version[*]"`, …), `BundleID`/`BundleType`, `Bundled`, `CanBeEmpty`, `EmptyFieldText`, `Values []BundleValue` and `Warnings []string`. Each `BundleValue` has `ID`, `Name`, `LocalizedName`, `Ordinal`, `Archived`, `Color`, plus the kind-specific `IsResolved *bool` (state), `Released`/`ReleaseDate` (version), `Owner` (ownedField), `Login`/`FullName`/`Email` (user), with `Label()` for display and `Resolved() (resolved, known bool)` for the default proposal.

Two implications for the persisted shape, if it helps: the stable key for a value is its `Name` — `ID` is instance-local and `LocalizedName` changes with the UI language — and `IsResolved` is deliberately a pointer, so "the instance never told us" is not stored as `false`. Nothing about the YAML shape is decided in `internal/youtrack`; that stays yours and `internal/config`'s. Full detail on GIT-T-0131.
