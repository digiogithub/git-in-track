Vault and MCP halves landed (`GIT-T-0033`, `GIT-T-0037`, `GIT-T-0045` done): `inbox.list` and `inbox.triage` in `internal/vault/inbox.go`, the `inbox` option on `item.create`, and the tools `create_inbox_item`, `list_inbox` and `triage_inbox_item` in `internal/mcp/tools_inbox.go`, with `docs/08-mcp-server.md` §4.11–4.13 updated. `GIT-T-0042` (REST + `inbox.changed`) is still `todo` — `internal/server/` belonged to another agent this wave — and carries a comment with the exact vault calls and error mapping the HTTP layer needs. The story is `in_progress`, not `done`.

Two things a reviewer must know.

**Accept cannot change `type`, and the criterion is left unticked.** An item id encodes its type (`GIT-US-0056` is a story because of the `US` segment), so changing the type means changing the id, which R-ID-3 forbids for life. `inbox.triage` accepts a `type` argument and refuses it with `invalid_request` when it differs, naming the way out: create the right type and mark this one `duplicate`. Status and parent do travel in the same rev-checked write, and the workflow transition is validated and `started`/`closed` stamped, because `FileStore.Update` already runs `checkTransition` and `stampTransition` when the patch carries a status — that is why the implementation uses `Update` rather than `MoveWith` plus a second patch, which would have been the two writes R-REV-3c forbids.

**The wildcard lives at the edges, not in the vault.** `inbox.triage` treats an empty rev as unconditional, exactly as `item.update` does; `requiredRev` in `internal/mcp` translates `"*"` into it, and `requireIfMatch` should do the same for `If-Match: *`. The vault never sees the literal `"*"`.

Smaller decisions worth a glance: `inbox.list` sets `SnoozeAsOf` from the vault clock itself so no surface can forget it; `counts` and `pending` are computed over the whole queue rather than the page, so the sidebar badge and the `inbox.changed` payload need no second call; accepting defaults to the workflow's initial status and refuses a triage status outright; rejecting moves to the first `cancelled` status and never deletes (ADR-026); `duplicate` writes both the `duplicates` link and the `duplicated_by` inverse inside one `WriteSet`, the target unconditionally since the caller quoted the entry's rev, not the target's.

They run against a new fixture, `internal/mcp/testdata/project-inbox/`, because the shared `project-basic` fixture deliberately declares no triage status and is read by `internal/core` and `internal/server` tests that would have to change with it.
