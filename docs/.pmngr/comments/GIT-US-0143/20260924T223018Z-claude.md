Implemented `gintrack migrate --to <schema>` and the upgrade guide.

- Core: `core.PlanSchemaMigration` (internal/core/schema.go) plans the bump on top of
  `UpgradeProjectSchema` (the one-line edit of the implicit upgrade and `doctor --fix`),
  refuses a downgrade, a newer or missing schema and an unsupported target, and returns the
  changed lines for the diff summary.
- CLI: cmd/gintrack/migrate.go (thin). `--dry-run`, `--json`, idempotent. Scope decision:
  the only project of the workspace, `--project KEY`, or `--all`; several projects without a
  selector is a usage error. All-or-nothing across projects; bytes re-checked before each write;
  no commit. Exit codes: 2 bad target/selector, 3 downgrade/newer/missing schema, 4 unknown
  project, 5 file changed between plan and write.
- Docs: new docs/14-upgrading-to-specs.md (linked from README and docs/README), docs/07 §4.22,
  docs/03 R-EVO-4 and R-SCHEMA-2-3, CHANGELOG (Added, upgrade note, 1.0 "Upgrading"
  paragraph), docs/12 §2/§5, AGENTS.md list of unimplemented behaviours.
- Tests: TestPlanSchemaMigration (core), TestMigrate and TestMigrateChangesOneLine (CLI), all on
  temporary fixtures. make lint and make test pass. This repository's own project.yaml was not
  touched.
