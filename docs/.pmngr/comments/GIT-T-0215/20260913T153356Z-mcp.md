What the documentation has to say, from the vault half that did land:

- Routes and status shape: see the comment on GIT-T-0214.
- The five states are `unlinked`, `in_sync`, `local_ahead`, `remote_ahead`, `conflict`, and `remote_ahead` is only ever reported when the caller asked for the remote read.
- Change detection is content-based, not byte-based. The `## Feedback` block is local-only and is rewritten on every write (ADR-030, R-FB-4), so its absence upstream is never evidence of a remote change; the comparison is `mapping.EqualContent` and the fingerprint recorded in `external.key` is taken over the content that actually crosses the boundary.
- Conflict semantics: last writer wins per direction; both sides changed writes `<page>.conflict.md` beside the page and leaves the original untouched, rather than merging.
- `youtrack.kb.conflict` belongs in §5.6 next to the `sync.job.*` events; the page write itself already produces `file.changed` through `publishPageWrite`.
