Closed: the last open criterion, "no secret appears in the generated file", is now met whenever a `pando` binary is available.

`gintrack agent init` resolves `pando` (PATH, or `--pando <path>`), runs `pando secret <companion token>` (with `--age-keys <set>` when given), validates the `age1:` prefix and writes `[MCPServers.gintrack.Auth] Type = 'bearer', Token = 'age1:…'`. Pando decrypts that on load and derives the `Authorization: Bearer …` header itself (`internal/config/mcp_auth.go` `AuthHeaders`, `internal/config/agecrypto.go`), so the `[MCPServers.gintrack.Headers]` block is no longer written. Without a usable `pando` the command refuses with exit 5 and writes nothing; `--plaintext-token` is the explicit escape hatch back to the literal header, still 0600, still with the SECURITY banner and now a stdout WARNING.

Evidence — `cmd/gintrack/agent.go` (`agentEncryptToken`, `agentResolvePando`, `agentRedact`; `os/exec` lives in `cmd/gintrack` only, never `internal/core`), `cmd/gintrack/templates/agent/pando.toml.tmpl`, and in `cmd/gintrack/agent_test.go` a fake `pando` on PATH that prints `age1:` + base64 of its argument:
`TestAgentInitWritesThePandoConfiguration`, `TestAgentInitKeepsTheSecretOutOfTheOtherFiles` (no clear token, no `Headers` block), `TestAgentInitEncryptsTheCompanionToken` (ciphertext identity, `--age-keys` forwarding, `tokenEncrypted: true`), `TestAgentInitPandoFlag`, `TestAgentInitRefusesWithoutPando`, `TestAgentInitRefusesABadSecretCommand` (4 sub-cases), `TestAgentInitPlaintextToken` (`tokenEncrypted: false`).

Verified: `go build ./...`, `go vet ./cmd/gintrack/...`, `go test -race ./cmd/gintrack/... -count=1`, golangci-lint v2.13.2 on `./cmd/gintrack/...` — all clean. Also run once against the real `~/bin/pando` in a throwaway temp directory: the file came out with `Token = 'age1:…'` and zero occurrences of the token.

Residual caveat, documented in docs/20, docs/07 and ADR-035: `pando secret` takes its value as an argv argument (it reads no stdin), so the token is briefly visible in the local process list; neither the token nor the ciphertext is ever printed.
