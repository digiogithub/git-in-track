Landed as `cmd/gintrack/agent.go` + `cmd/gintrack/agent_test.go`, with the embedded templates under `cmd/gintrack/templates/agent/` and one registration line in `cmd/gintrack/root.go`.

`gintrack agent init [--repo <path>] [--companion-url <url>] [--agui-port 8090] [--force] [--json]` writes, at the repository root: `.pando.toml` (0600), `agents/personas/backlog-assistant.md`, `agents/skills/gintrack-search/SKILL.md`. It also creates, once, an AG-UI bearer token at `<stateDir>/agui/<repo id>.token` (0600, outside the repository) so the printed `pando agui-serve --token-file <f>` is actually runnable; a re-run never regenerates it. It prints the two next commands and never prints a token value.

Values verified against Pando's `internal/config/config.go` rather than the stale `pando-schema.json`, and then against a live `pando agui-serve` — see the comment on GIT-T-0118.

**One acceptance criterion could not be met as written.** "No token value is written into any file inside the repository." Pando does **not** expand environment variables inside an MCP server's `Headers` (checked `internal/config/config.go`, `internal/config/mcp_auth.go`, `internal/mcpauth/`; the only `os.ExpandEnv` is on TLS *paths*), and `.pando.toml` has to live in the `agui-serve --cwd`, which is the repository. So the companion bearer token is written literally into `[MCPServers.gintrack.Headers] Authorization`. Mitigations actually implemented: mode 0600 (re-applied with an explicit `chmod` so `--force` over a 0644 leftover is fixed too), a SECURITY banner at the top of the generated file, a stdout warning telling the user to git-ignore it, and tests asserting the persona and the skill never carry it and that the AG-UI token never enters the repository at all. When no companion token is configured the header is written commented-out, not empty. This is recorded as a negative consequence in ADR-035 and in docs/20 section 6.

Reviewer should look at: the refusal path (`exitConflict`, nothing written, names the file), `agentCompanionURL` (wildcard bind → loopback, IPv6 bracketing), `tomlString` quoting, and the `Tools` glob being `gintrack_*` with one underscore — Pando names a gateway tool `<server>_<tool>`.

`go build ./cmd/... && go vet ./cmd/gintrack/... && go test -race ./cmd/gintrack/...` all pass (9 new tests). `go build ./...` fails in `internal/pando` (`errors.go:74: undefined: statusText`) — another agent's in-flight work in the same wave, unrelated to this change.
