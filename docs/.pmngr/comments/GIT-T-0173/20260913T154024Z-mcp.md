Left `todo`: `internal/server` is owned by another agent this wave.

Half of this is already in place and needs no new mechanism. Every queued push carries `YouTrackJob.Key = <comment path>`, and `syncengine.Engine.Enqueue` already folds two queued jobs that share a kind and a key into one (see `TestEnqueueCoalescesByKey` in `internal/syncengine/engine_test.go`). So repeated writes to one comment path collapse to one job, and different comment paths stay separate jobs, as long as the server maps `YouTrackJob.Key` onto `syncengine.Request.Key` — which `internal/server/youtrackjobs.go` does.

`TestCommentPushIsCoalescedPerCommentPath` in `internal/vault/youtrackpush_test.go` pins the key the vault emits.

What is genuinely left is the *debounce*: the engine coalesces jobs still queued, not a job that has already started, so a burst spread across a running job produces two. If that matters, add the `arm`/`time.AfterFunc`/`fire` window of `internal/gitops/committer.go:157-211` in `internal/server` between the seam and `Enqueue`, keyed the same way, with a fake clock in the test. Do not put the timer in the vault: it compiles to WebAssembly and must not own background timers.
