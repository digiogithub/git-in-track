`internal/pando/doc.go` landed with the package contract and all the rationales: why MCP rather than REST (Pando has no REST search API; the searches exist only as MCP tools), why `kb_search_documents` and `code_hybrid_search` are called separately rather than through `hybrid_search_remembrances` (its merge sorts incommensurable scores — KB RRF around 0.016 against boosted code scores around 1.0 — so the code side always wins and KB hits fall off the end), why the transport is restricted to loopback, the TOON result format and where `code_hybrid_search` differs, the session-reuse rationale (Pando's session map has no eviction), and the error vocabulary.

The honest caveat is in there as its own paragraph: **loopback binding is not a boundary against the user's own browser.** Pando's MCP HTTP transport now requires a bearer token, but it still serves CORS `*` with global auto-approve, so while that policy stands any web page the user visits can reach `127.0.0.1:9777` from their browser with no companion involved. Loopback keeps the network out; it does not keep a hostile page out. That is PANDO-EP-0006's to fix.
