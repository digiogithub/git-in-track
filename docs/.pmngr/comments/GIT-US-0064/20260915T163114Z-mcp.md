**What a reviewer should look at**
- `tools/registry.ts` — `toolDeclarations()` returns one frozen module-level array (asserted with `toBe`), so Pando's agent-pool key (`agentpool.go:54-77`) cannot move between turns.
- `assertNoHitlShadowing` runs at **import time**: a registry entry named `pando_permission_request` or `AskUserQuestion` would route an approval through an executor that answers it.
- `createToolRunner().run()` always resolves with a JSON string — unknown name, failed validation and a throwing executor all become `{error: …}`. A throw would leave the run suspended for Pando's 10-minute window, which reads as a frozen app.
- No router import anywhere in `tools/`: navigation arrives as `ToolContext.navigate` from `AgentPage`'s `useNavigate()`, and every test passes a spy.
- `apply_backlog_filter` round-trips through `parseItemSearch`/`toSearchInput`, and the test asserts the emitted params against `validateItemSearch` itself. Strict zod (`z.strictObject`) is what turns an invented field into a named error rather than a silently ignored key.
- `show_items` resolves through `ToolContext.lookup.item`, wired in the page to `queryClient.ensureQueryData(backlogKeys.detail(...))` — a cache read that only becomes a request for an item nobody fetched; ids are de-duplicated before lookup. The cards render from the **tool result** (`ui/ItemCards.tsx` via `renderToolResult`), so an old turn keeps showing what the agent showed then.
