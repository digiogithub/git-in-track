Landed `ActiveCycle`, `CloseSprintDialog`, derived-status grouping in `SprintList`, dateless drafts in `NewSprintDialog`, and the provider half: `SprintSummary.status` and `.snapshot`, `closeSprint(id, {carry, transfer, dryRun, rev})`, a new `transferSprintItems`, and `sprint.changed` bridged into the cache. 245 tests green across boards/metrics/api; lint, tsc, tokens and build clean.

Three decisions worth a reviewer's attention. The dry-run preview is modelled as a **query**, not a mutation — a dry run is a read that computes a report — keyed by the chosen destination so switching destination re-runs it, and both close and transfer mutations skip invalidation entirely when `result.dryRun` is true: nothing was written, and invalidating would imply otherwise. The per-item refusals gate the confirm button behind an acknowledgement checkbox that resets on every new preview; "this project is not cloned, so these three will not move" is the whole point of the preview, and a button merely next to the banner is too easy to click past. And `SprintPanel` deliberately shows two badges, because the stored lifecycle `state` and the derived `status` are different facts — an `active` sprint whose end date has passed reads as `completed`.

`SprintMetrics` was corrected in the same pass, which was not in the story text but is required by it: a snapshot-backed answer carries an empty `flow` and zeroed `stats` because the cumulative-flow series is not frozen at the close, so those panels now say "not recorded" instead of drawing zeros a reader would take for measurements.
