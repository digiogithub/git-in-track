Root cause, confirmed by `git log -S`: commit c09f02d (2026-09-13, "feat(cli): drive the
integration from a terminal, and triage, cycles and KB sync in the UI") is the first to carry
the corrupted lines, in the same hunk that bumps `counters.task` 223 -> 225 and reformats the
whole file (alignment, blank lines and the folded description lost). That is the signature of
`Allocator.writeCounter` -> `setYAMLPath`, which re-encoded the full yaml.v3 node tree.

The writer did not drop quotes: the original hand-written entries were never quoted.
`{ name: core, ..., description: Shared Go core (model, parser, index) }` already parsed as
`description: "Shared Go core (model"` plus null keys `parser` and `index)`, because a comma
ends a plain scalar inside a flow mapping. The re-encode faithfully re-emitted that tree, turning
the latent ambiguity into visible `parser: ''` keys.

Fix: `setYAMLPath` now splices the one value into the original bytes (replace a plain scalar
token, or insert missing keys as new lines under a block mapping), guarded by a check that the
result decodes to exactly the original document with that value set; other shapes fall back to
the node re-encode. `Label` records unexpected keys and `Validate` reports them as
`W-PROJ-LABEL-KEYS`, which `gintrack doctor` prints. The two descriptions in this repo's
project.yaml are restored and quoted (two-line diff).

Out of scope, noted: `internal/config/projectlink.go` (integrations block writer) still
re-encodes project.yaml through the node tree and would reformat it the same way.
