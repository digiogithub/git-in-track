Left `todo`: `cmd/gintrack` is owned by another agent this wave, so GIT-US-0062 landed with its MCP half only.

`gintrack youtrack import <query|ids...>` calls the vault directly, no new plumbing needed:

- `--dry-run` → `youtrack.import.preview` with `{project, query, ids, depth, includeLinks, includeComments, includeAttachments}`; answers `{project, issues: [{youtrackId, title, mappedType, action, targetId, parent, milestone, depth, comments, warnings}], warnings}`.
- without it → `youtrack.import.run`, same parameters; answers `{project, issues: [{youtrackId, itemId, action, comments, warnings, error}], created, updated, failed, warnings, writes}`.

Give `query` or `ids`, never both, and bound `--depth` to 0–5 (`vault.YouTrackMaxDepth`); both rules are already enforced by the vault with field-level `invalid_request` errors, so the command only has to render them.

The table output wants issue, action and resulting item id — `youtrackId`, `action`, `itemId` map one to one. `warnings[]` are `{field, value, fallback, reason}` and belong on stderr in `--json` mode.

The parent `youtrack` cobra command already exists in `cmd/gintrack/youtrack.go` (the `connect` subcommand): extend it, do not create a second one. The MCP equivalent that landed is `import_youtrack_issues` in `internal/mcp/tools_youtrack.go` — worth reading for the argument validation the command should mirror.

Also still open in `cmd/`: the long help in `cmd/gintrack/mcp.go:33-38` enumerates thirteen tools and is now four short (see GIT-T-0119).
