Landed the command-line half of the companion: `internal/config` (schema,
per-platform path, precedence chain, repository registration) and the command
surface in `cmd/gintrack` — `add`, `ls`, `rm`, `index`, `item
list|get|new|edit|move|comment|link`, `doctor` and `config path|show|init`,
all rendering through the shared `cmd/gintrack/output` package.

The serve wiring and the watcher are untouched and still belong to this story.
Two notes for whoever picks them up: `openVault` in `cmd/gintrack/workspace.go`
already mounts every registered repository as one `core.FS` and builds a single
index over them, and `internal/config` exposes `Resolve`, so `serve` only has to
read `server.bind`, `server.port`, `server.token` and `index.watch` from the
resolved configuration.

Deferred with a reason recorded in docs/07: `item get --render`,
`item new --template`, `item edit --editor`, `add --key/--init`, and the index
snapshot flags.
