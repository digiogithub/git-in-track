The seam landed one level below where the story put it, and is better for it: `Vault.autoPushComment` in `internal/vault/youtrackpush.go`, called from `comment.add` after the vault lock is released. REST, the web app, MCP and the CLI all dispatch `comment.add`, so there is exactly one decision, no per-surface copy, and no way for a surface to forget it. GIT-T-0171 is `done`; GIT-T-0164, GIT-T-0167 and GIT-T-0173 are left `todo` because `internal/server` and `internal/config` belong to other agents this wave — each carries a comment saying precisely what is left.

Reviewer must know three things. The enqueue uses `context.WithoutCancel`, so a closing HTTP response cannot cancel it, and it runs outside the mutex, so saving a comment waits on nothing but the file system. The no-feedback-loop guard is the comment's own `external` reference rather than a changed-field check — strictly stronger, since it also holds for a comment rewritten for any other reason. Coalescing comes free from the engine: `YouTrackJob.Key` is the comment path and `syncengine` already folds queued jobs sharing a kind and a key; only the debounce *window* is still open, and it must live in `internal/server`, never in the vault, which compiles to WebAssembly and owns no timers.
