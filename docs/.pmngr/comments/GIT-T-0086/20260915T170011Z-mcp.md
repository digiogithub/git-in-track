Closing the last failing criterion: `focus_board_card` now actually finds a card.

`focusBoardCardInDom` selected `[data-item-id="<id>"]`, an attribute no component emitted — board cards render `<li data-ref="<project>/<id>">` — so the executor answered `focused: false` against a board that was showing the card. Fixed at the source of truth: `web/src/features/boards/BoardCardTile.tsx` now renders `data-item-id={bareItemId(card.item)}` on the same `<li>`, keeping `data-ref` (the dnd-kit and board tests key on it). `web/src/features/agent/tools/navigation.ts` reduces its argument with `bareItemId` before building the selector, so `GIT/GIT-US-0061` and `GIT-US-0061` find the same card.

A second, real bug fell out of writing the test: `const escape = globalThis.CSS?.escape` detaches `CSS.escape` from its receiver, and the WebIDL binding throws `'escape' called on an object that is not a valid instance of CSS`. Every id containing a character worth escaping would have thrown at runtime. It is now called on `CSS`.

Tests: `registry.test.ts` > `focus_board_card` > "finds the card a board renders and scrolls it into view" (jsdom: renders the `<li>` a board card produces, stubs `scrollIntoView`, asserts it is called with `{block:'center'}` for both the bare and the qualified id); `BoardView.test.tsx` > "shows id, title, assignees, labels, priority and estimate on a card" now also asserts the rendered card carries `data-item-id`. `npx vitest run src/features/agent src/features/boards src/api` 430/430, `tsc --noEmit`, eslint and prettier clean.
