**Fails — "Each tool navigates through TanStack Router to an existing route and returns a result describing the outcome"**, for `focus_board_card` only. The default focus walk selects `[data-item-id="<id>"]` (`web/src/features/agent/tools/navigation.ts:69-70`), but no component in `web/src` ever emits that attribute: a board card is `<li data-ref={card.ref}>` with `ref` shaped `<projectKey>/<itemId>` (`web/src/features/boards/BoardCardTile.tsx:55-58`, `web/src/api/provider.ts:2360-2362`). `AgentPage` builds the `ToolContext` without a `focusCard` override (`ui/AgentPage.tsx:101-124`), so in the real app the walk always times out after 600 ms and the tool reports `focused: false` with "The board opened, but that card is not on it." for cards that are on it. The tests never catch it because every `focus_board_card` case injects a `focusCard` spy (`tools/registry.test.ts:188,202,209`) and the DOM path has no test at all.

Smallest fix: add `data-item-id={bareItemId(card.item)}` to the `<li>` in `BoardCardTile.tsx:55`, or match the existing attribute in `navigation.ts:70` with `[data-ref$="/${itemId}"]`; then cover `focusBoardCardInDom` with a jsdom test.
