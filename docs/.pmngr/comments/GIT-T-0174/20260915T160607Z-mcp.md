Server half landed: `handleCapabilities` now reports `"search": s.search.backend()`, which is `"pando"` only while a backend is installed **and** the last semantic leg did not fail — so a configured-but-down Pando reports `"core"`, and the value flips back by itself on the first successful query. Verified in `TestSearchDegradesWhenPandoFails`, which reads `/api/v1/capabilities` after each failure mode, and in `TestSearchRecoversAfterADegradation`.

The web half was landed by the sibling search wave: `Capabilities.fullTextSearch` is `'core' | 'bleve' | 'pando'` (`web/src/api/provider.ts`), `toFullTextSearch` maps the third value in `companion-provider.ts`, and `browser-provider.ts` keeps reporting `'core'`. `bleve` stays in the union although it is not shipped; docs/02 §8 and docs/07 say so.
