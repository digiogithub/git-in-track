**What a reviewer should look at**
1. `MessageBubble.tsx` — agent output goes through `@/markdown` (public `index.ts`), so sanitisation runs last; `externalImages: false`, `wikilinks: false`. Tool args/results are escaped `<pre>`, never Markdown. Streaming parses a throttled prefix (~120 ms, trailing edge) and renders the tail as plain text, with a caret; highlighting waits for the end of the stream.
2. `AgentPage.tsx` mount order — `attach` → `refreshThreads` → `reattach()` **only when the adapter still lists the restored thread**. Re-attaching to a thread id Pando has never seen would fail on `getAgentThreadMessages` and put an error banner on an empty page. A store-level `hydrate()` action would let a known-but-idle thread restore its transcript without opening a reattach stream; not added, because the store was out of scope.
3. The interrupt seam for wave 3 — `AgentPage` prop `renderInterrupt?: (props: { interrupt, resume, cancel, readOnly }) => ReactNode`, fallback `DefaultInterrupt` in `ui/InterruptSlot.tsx`. Same for the right rail: `renderRail?: () => ReactNode`. Wave 3 changes one file or passes a prop.
4. Thread titles live under `gintrack:agent:threads` as `{ [repo]: { id, title, updatedAt }[] }` — the key the story names, shaped per repository so it does not collide with `gintrack:agent-threads:<repo>` from `threads.ts`.

**Not met / deferred**
- Read-only (another tab owns the thread) is covered at the `Composer` level, not end to end through `AgentPage`: the tab guard is constructed inside `store.attach` and the page has no seam to inject a fake one. Store tests already cover the guard.
- "Stop cancels the in-flight run" is asserted by staging `runStatus: 'running'` and clicking Stop (the wiring, the `cancelAgentRun` call and the settled state); the scripted fake stream settles in microtasks, so racing a real in-flight stream is not reproducible.
- Auto-scroll is implemented and reasoned about but not asserted: jsdom reports zero for every scroll metric, so a test would assert nothing.
