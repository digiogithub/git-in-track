Rewrote the central assumption and the sync model against report A1/A2/A5/A7 and the 2026-09-13 decisions.

Changed:
- Removed the wrong claim that everything beyond `tags`/`aliases` "lands in the searchable metadata". Front matter is now written for readability and tags only; the story states plainly that the exporter must not rely on a metadata round-trip, and adds writing the item id into the body so it survives into the chunk.
- Sync model is `KBAutoImport = true`, `KBWatch = false` (the watcher erases tags on every edit), with re-sync driven by the companion: wait for the next auto-import pass today, REST reindex later.
- New acceptance criterion: a hub subscriber overflow triggers a full re-export rather than a silent desync, with a test that drives the overflow. The hub drops slow subscribers permanently (`internal/server/hub.go:113-141`, verified in the tree), and the story now prefers driving the exporter from the publishers directly over an SSE-shaped `hubClient`.
- The metadata round-trip contract is split out as a Note, explicitly not a gate on this story.
- Line references refreshed: `events.go:256, :282` -> the publishers at `:293` and `:359`, payload structs `:178`/`:188`, `IsKb` `:195`; `hub.go:141` -> subscribe API `:79-104`/`:212`, overflow policy `:113-141`. Dropped the `watcher.go:194-225` claim, which belonged to the now-disabled watcher path.
- Reversed the `kb_add_document` rationale: the pull path wins on write pattern, not on fidelity — both lose metadata today.
