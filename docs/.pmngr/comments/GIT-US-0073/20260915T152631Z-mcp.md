Wave 1 landed: the exporter package and its documentation. Staying **in_progress** — the server wiring (GIT-T-0130, GIT-T-0134) is wave 2's.

**Files:** new package `internal/pandosync/` (`doc.go`, `document.go`, `paths.go`, `exporter.go`, `document_test.go`, `exporter_test.go`), new `docs/21-semantic-search.md`, one row added to the table in `docs/README.md`.

**Deviations from the story body, all deliberate:**
1. `internal/pandosync` rather than `internal/server/pandosync.go`. It depends on `internal/core` and `internal/vault` only. It must not import `internal/server`: the hub lives there, so `Event` is defined here and the server adapts to it, which is also what the story's "drive the exporter from the publishers rather than from an SSE-shaped hubClient" asks for.
2. The corpus root is `Options.Dir`, not `config.Config.CacheDir(configPath)` — importing `internal/config` here would be the same coupling. Wave 2 passes `CacheDir(configPath) + "/pando-kb"`. `New` refuses a root that is a git working tree, so nothing exported can ever land in a repository.
3. Front matter carries `id`, `type`, `title`, `status`, `milestone`, `parent`, `project`, `updated`, `tags`, `aliases` as the AC asks, but per the 2026-09-13 realignment the document does not depend on any of it round-tripping: the id is repeated as the first body line, inside the indexed chunk, and `tags` leads with the id.

**Acceptance criteria:** full export layout, front matter + id in body, single-item rewrite, KB page rewrite, overflow → full re-export (driven in `TestApplyOverflowTriggersAFullExport`), atomic writes (op sequence asserted through a spy FS), unchanged re-export writing nothing, path-escape refusal, and a 10 000-item timing check are all covered. `go test -race ./internal/pandosync/...` is green at 87.3% statement coverage; `go vet` and `gofmt` clean.

**Not met here:** "does not block server start" and the hub subscription, both of which need `internal/server`. `CHANGELOG.md` is likewise outside this wave's ownership — the entry is handed to the coordinator in the implementation report.

**Reviewer should look at:** `paths.go` (the traversal guard, and why the temp file is a dot file without `.md`), `writeIfChanged`/`atomicWrite` in `exporter.go`, and `applyRemovePage`'s fallback to a full export when a removed page cannot be resolved to a corpus path — the one case where "do nothing" would have desynced silently.
