Left `todo` on purpose: `internal/server` is owned by another agent this wave, so the vault half of GIT-US-0090 landed without its REST routes.

The three handlers are thin `s.call(...)` wrappers over the core methods that now exist:

- `GET /api/v1/youtrack/kb/status?path=&recursive=&remote=` → `youtrack.kb.status` with `{project, path, recursive, remote}`. Answers `{project, pages: [{path, linked, articleId, url, state, syncedAt, error?}], remote}`. `state` is one of `unlinked`, `in_sync`, `local_ahead`, `remote_ahead`, `conflict`. **`remote` must stay opt-in and must not be defaulted on by the route**: it is one article read per page, and a tree view would turn into hundreds of requests.
- `POST /api/v1/youtrack/kb/publish` → `youtrack.kb.publish` with `{project, path, recursive}`. Answers `{project, jobId, pages: []}`.
- `POST /api/v1/youtrack/kb/pull` → `youtrack.kb.pull`, same shape.

Both queueing methods already return `unavailable` when no engine or no client is installed and `not_found` when the path matches no page, so the handler needs no logic of its own beyond parsing and the `features.youtrack` gate.

The companion must install the engine seam for any of this to work: `vault.Vault.SetYouTrackEnqueuer(func(ctx, vault.YouTrackJob) (string, error))`, alongside the existing `SetYouTrackProvider`. The job kinds are `vault.JobKindKBPublish`, `vault.JobKindKBPull` and `vault.JobKindCommentPush`, and `YouTrackJob.Key` is the coalescing key the engine folds duplicates on.
