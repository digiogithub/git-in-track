Landed: the whole dialog — `ImportQueryBar`, `ImportOptions`, `ImportPreviewTable`, `ImportDialog`, `ImportButton` (the backlog toolbar entry), `import-model.ts` and `queries.ts` under `web/src/features/youtrack/` — plus `searchYouTrackIssues`, `previewYouTrackImport` and `runYouTrackImport` on `DataProvider` and all three providers. 13 Vitest cases cover searching, empty, selection, keyboard, presets, preview with warnings, option wiring, progress, cancellation and partial failure.

Two things a reviewer must know. **The API it calls does not exist yet**: `GET /api/v1/youtrack/issues` is GIT-US-0054 (still `backlog`) and the import preview/run routes have no REST surface at all — the vault methods of GIT-US-0047 are there, nothing exposes them over HTTP, and no story covers that. I did not add them: `internal/server` belongs to another agent this wave. **The companion request shapes I wrote are therefore a proposal**, and the one the server side should implement verbatim is: `POST /api/v1/youtrack/import/preview?key=<gintrackKey>` and `POST /api/v1/youtrack/import?key=<gintrackKey>`, both taking `internal/vault`'s `YouTrackImportParams` as the body; preview answers `YouTrackImportPreview`, and run answers either `{"jobId": "job_000021"}` when it enqueues on the engine or the whole `YouTrackImportResult` when it runs inline (the client reads both).

Second: the toolbar entry is gated on `youtrackSupported && youtrack`, and `youtrack` is workspace-wide — it says *some* mounted project is linked, not which — so in a workspace mixing a linked and an unlinked project the entry appears on both backlogs. Making it exact needs either a per-project capability or a cheap `GET /youtrack/settings?key=` probe on mount; worth a small story rather than a guess.
