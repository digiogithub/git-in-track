Closed. Six of the eight criteria were verified against the code and docs as they stand; two needed work.

Verified, not assumed. `cmd/gintrack/root.go` registers `newSprintCommand` and `cmd/gintrack/sprint.go` carries `list`, `show`, `start`, `close` and `transfer` with the shared arg validators and printer path. `sprintRowPayload` carries both `state` (the stored lifecycle field) and `status` (derived on every read), plus `snapshot` as a pointer that is absent while the sprint is open — so the second criterion's "JSON carries the derived status and the snapshot when present" is literally true. The dry-run and per-item-refusal behaviour is GIT-T-0178, done and tested. `docs/07` §5.5 documents the extended close and the standalone transfer with worked shapes and their error codes (`sprint_target_completed`, the `repo_not_cloned` per-item line that is a `200` and not a failure), and `sprint.changed` is in the §5.6 contract section. `docs/08` §4 lists `close_sprint` and `transfer_sprint_items`; ADR-034 is in `docs/adr/README.md`.

Two things were genuinely stale and are fixed.

**§4.6 still described `gintrack board` as built**, with worked terminal output, under a confusing "*As built.* Only the board subcommands above are planned" line. There is no `board` command and no `retro` command — `root.go` registers neither and `cmd/gintrack/` holds no `board.go`. §4.6 is now titled "not implemented", says so first, points at the REST routes and the Markdown files that do work, keeps the planned tree labelled as planned, and drops the invented transcripts. Note the numbering deviation recorded in the body: the sprint tree stayed at §4.16 rather than taking over §4.6, so that the record of what is unbuilt survives.

**`CHANGELOG.md` and `docs/04` §8 both still carried a mid-epic caveat that is now false.** The CHANGELOG claimed dateless sprints were "still refused by `sprint.create` and `sprint.update`" and that "`sprint.close` does not write [a snapshot] yet and the metrics do not read one back yet"; docs/04 §8's header pointed at §8.2 for markers of what was "still model-only". I checked all three against the code before rewriting: `internal/vault/sprint.go` parks a dateless sprint as a draft, `SprintClose` freezes the snapshot before any carry decision rewrites an item out of the scope, and `internal/vault/metrics.go` answers a closed sprint from `core.SprintMetricsFromSnapshot` without touching git at all. Both documents now say the feature is wired end to end, and both carry the backward-compatibility note: existing sprint files parse unchanged and gain a `snapshot` only when they are next closed.

`go build ./...`, `go test -race ./...`, `gofmt -l internal cmd`, `GOOS=js GOARCH=wasm go build ./...` and `make lint` are all clean.
