Landed, **not** as `events.ts`. Per the 2026-09-13 realignment, the SDK's `PandoThread` *is* the reducer: it folds `TEXT_MESSAGE_START|CONTENT`, `TOOL_CALL_START|ARGS|END|RESULT` (arguments accumulated as a string and parsed only at the end), `REASONING_MESSAGE_CONTENT`, `STATE_SNAPSHOT`, `STATE_DELTA` via its own `applyJsonPatch`, `CUSTOM` and `RUN_FINISHED{outcome}`, with a `default:` branch that ignores anything else. Writing a parallel one was explicitly ruled out, so `web/src/features/agent/threads.ts` composes it and adds only the gaps.

**What is the SDK's:** the transcript, the tool-call index, argument accumulation, the shared-state document and its RFC 6902 patcher, the interrupt flag and `pendingToolCalls`, the trailing-`tool`-message resume, and `parseSSE`.

**What is local, and why (each one is a case the SDK has no code for):**
- `supplementaryReduce()` — `MESSAGES_SNAPSHOT`, `TEXT_MESSAGE_CHUNK`, `ACTIVITY_SNAPSHOT`. All three carry transcript content and all three fall into the SDK's `default:` branch.
- The unapplicable-patch rule. `PandoThread.applyStateDelta` **throws** on a patch it cannot apply and on any `STATE_DELTA` before the first snapshot; that throw happens inside the `for await` driving the reduction, so it kills the generator and costs the user the rest of the reply. The acceptance criterion says such a patch is ignored, so `client.ts` filters the event out *before* the thread sees it, deciding with the SDK's own `applyJsonPatch` against a throwaway clone (`patchApplies()`). The SDK stays the only implementation of the patch semantics.
- `toAgentMessages()` — the render projection (see the GIT-US-0053 comment for the shape). It never mutates the transcript, which has to stay exactly as the wire wants it.
- `hydrate()` / `reattach()` — the server-side thread API, which `PandoThread`'s own doc comment says it never calls.

One wart worth a reviewer's eye: `AgentThread.reattach()` drives the re-attached stream through `thread.send('')` with the transport swapped out (`streamOverride`), then pops the placeholder message, because `PandoThread.reduce` is private and reachable only by driving a run. Nothing is posted — the override replaces the POST entirely — and the placeholder is removed synchronously, before any event can observe it. The alternative was a second reducer, which the story forbids.

Fixtures are `web/src/features/agent/fixtures.ts`: `@pando-ai/sdk@0.2.0` ships no SSE fixtures (`files: [dist, README.md, LICENSE]`), so they are written from the wire shapes in `internal/agui/events.go` as the SDK's own `.d.ts` mirrors them. They are event arrays; raw `data:` frames (split mid-frame) are exercised where the parser actually lives, in `companion-provider.test.ts`.

Tests: `threads.test.ts` (15) and the reducer-facing half of `store.test.ts` — ordered interleaving of text/reasoning/tool calls, snapshot-then-delta, a bad patch ignored without corrupting state, a delta before any snapshot, an end without a start, an unknown event type.
