**(c) fail.** No `pando_permission_request` interrupt is ever emitted (no `perm-…` tool call id anywhere in the stream), so there was nothing to answer with `{"approved":true}`. The run does not fail closed either — it hangs indefinitely. Setting `AutoApprove = true` and restarting did **not** change anything: same hang, which is the tell.

Cause, from Pando's source:

- `GetMcpTools` caches the MCP-backed tools in a **package-level** `mcpTools` slice and returns it regardless of the permission service the caller passes — `internal/llm/agent/mcp-tools.go:253-256`.
- `app.New` builds the coder agent (and therefore the MCP tools) at startup with `app.Permissions` — `internal/app/app.go:731-741`. That happens before the AG-UI runtime exists.
- The AG-UI pool then builds its agent with the adapter's own permission service (`agentpool.buildToolsLocked` → `CoderAgentToolsWithMesnada(…, p.perms, …)`), but `GetMcpTools` hands back the cached tools still bound to `app.Permissions`.
- `mcpTool.Run` asks `b.permissions.Request(...)` — `internal/llm/agent/mcp-tools.go:156` — i.e. `app.Permissions`, where `installPermissionPolicy` (`internal/agui/hitl.go:49-62`) has registered no session handler and where `AGUI.AutoApprove` is not consulted. `permissionService.Request` finds no handler, no auto-approve, publishes a request for a TUI that does not exist in `agui-serve`, and blocks on `resp := <-respCh` forever — `internal/permission/permission.go:129-192`.

Net effect: with the gateway off, **every** `gintrack_*` call from an AG-UI run deadlocks. This is a Pando bug, not a gintrack one, and it is the blocker for this task. Options, none of them in this repo: a Pando fix (drop the cache or key it by permission service / register the AG-UI handler on the app service), or keeping the gateway on and accepting the coarse `mcp_call_tool` proxy documented in the previous comment (which does complete: it answered `8` with real ids). Suggest a PANDO-* item for the cache bug, and that GIT-US-0069 not claim a working chat turn over `gintrack_*` until it lands.
