Verified against a live Pando (`~/bin/pando` v0.705.1-0.20260914211356-c539b6039b76), 2026-09-15.

**What was run.** A scratch copy of this repository's `docs/.pmngr` plus `README.md` in a temp directory, then:

```
GINTRACK_CONFIG=<tmp>/state/config.yaml GINTRACK_TOKEN=live-check-token \
  gintrack agent init --repo <tmp>/git-in-track --agui-port 18090 --json
pando agui-serve --cwd <tmp>/git-in-track --port 18090 --no-tls \
  --token-file <tmp>/state/agui/git-in-track.token
```

**Observed.**

- `GET /api/v1/agui/healthz` (no token) → 200 `{"status":"ok","version":"v0.705.1-…","maxConcurrentRuns":4,"draining":false}`. `maxConcurrentRuns: 4` is the generated `[AGUI] MaxConcurrentRuns`, so Pando read the generated `.pando.toml`.
- `GET /api/v1/agui/info` with the bearer token → 200, agents `["coder", "backlog-assistant"]`, the profile described as `Pando profile backlog-assistant (base coder)` at `http://127.0.0.1:18090/api/v1/agui/backlog-assistant`. So `[AGUI.Profiles.backlog-assistant]` is accepted and addressable as `POST {path}/{agent}`.
- `GET /api/v1/agui/info` with no token → **401**, confirming `RequireToken = true`.
- Startup banner printed `Persona: backlog-assistant`, with no "unknown persona" warning; `[PersonaAutoSelect] PersonaPath = './agents/personas'` is what makes the generated persona loadable.
- `capabilities` → `{"frontendTools": true, "humanInTheLoop": true, "sharedState": true, "interrupts": true}`.

**Template error found and fixed by this run.** The first attempt reported `"frontendTools": false`. Pando's documented default for `[AGUI] FrontendTools` is `true`, but that default only applies while the key is absent from every config file: writing an `[AGUI]` section without it decodes to the zero value and silently turns frontend tools off. The template now states `FrontendTools = true` explicitly, and the re-run reported `true`. A test asserts the key is present.

**Second correction, from reading Pando's source rather than from the run.** MCP gateway tools are named `<server>_<tool>` (`internal/llm/agent/mcp-tools.go:75`, `fmt.Sprintf("%s_%s", …)`), so the allow-list glob is `gintrack_*`, not the `gintrack__*` the plan carried.
