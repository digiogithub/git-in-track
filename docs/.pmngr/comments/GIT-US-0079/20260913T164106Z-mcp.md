`gintrack youtrack push-comments <ITEM-ID>` landed with `--all`, `--comment`, `--wait` and `--json`, and `docs/07` §4.15 documents it, the "pushed means queued" rule and the permanent delete asymmetry.

Two things a reviewer must know. `--wait` re-reads the push result after the job ends rather than reprinting the queueing answer, so the remote ids in the table are the ones the job actually wrote back. And the automatic half of this epic finally works: `youtrackLinkOf` was not carrying `push_comments` into `vault.YouTrackLink`, so `Vault.autoPushComment`'s `auto` branch could never be true — the setting now reaches it, and the server logs the decision once per item rather than once per comment (GIT-T-0164).
