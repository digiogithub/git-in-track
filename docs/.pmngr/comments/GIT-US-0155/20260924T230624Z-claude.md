Implemented in jj change on top of main (no Phase 11 stack).

**Fix.** `list_items` and `list_inbox` passed the core cursor through untouched, and the
core binds it to the sort only. Both now wrap the core cursor in the same opaque MCP token
the offset-paged tools use, carrying a fingerprint of every filter plus the sort/order
(`internal/mcp/page.go`: `wrapCursor` / `unwrapCursor`). A mismatch — or a cursor from
another tool — is refused with `invalid_cursor`. `limit` and `fields` are excluded, so
they may still change mid-walk. `updatedSince` is fingerprinted as the raw argument, so a
relative value such as `7d` does not break its own walk as the clock moves. The
fingerprint now hashes JSON instead of `fmt.Sprint`, so `["a b"]` and `["a","b"]` differ.

**Checked on this base.** `search_items`, `search_kb` (query, project) and
`list_kb_pages` (project, prefix) already fingerprinted every input: no gap.
`search_semantic` has no cursor.

**Follow-ups.**
- Phase 11 stack: check `list_requirements` and `spec_coverage` (and any other cursor
  tool added there) — every filter and the sort must be in the fingerprint; if either
  passes a core cursor through, wrap it with `wrapCursor`/`unwrapCursor` once this lands.
  If GIT-SP-0004 is merged, its pagination requirement needs a MODIFIED Spec Delta.
- Outside MCP the core cursor is still bound to the sort only: `GET /api/v1/items`,
  `/api/v1/inbox` and the browser vault accept a changed filter mid-walk. Candidate
  backlog item (fix in `internal/core` `Index.Items`; note a relative `updatedSince`
  resolves to a moving timestamp, so the core would need the raw value to fingerprint).

Tests: `TestListItemsCursorIsBoundToTheFilter`, `TestListInbox` subtest (both failed
before the fix). `make lint`, `make test`, `make wasm` pass.
