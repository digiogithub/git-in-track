Maintainer answered both open questions, 2026-09-15. Two amendments to the acceptance criteria, now in implementation.

**Zero values count as unset, inside `[AGUI]` only.** An existing `[AGUI]` key holding `''`, `0`, `false` or `[]` is treated as absent and takes the template's value with no divergence reported. Every other shared table keeps warn-do-not-overwrite unchanged — `[MCPServer] StdioEnabled = false` is still reported rather than written. Scoped rather than uniform because a uniform rule would silently flip `StdioEnabled`, which this task's notes list as a warn key. Effect: one `agent init` over a real Pando config now leaves a working AG-UI listener instead of a report the user has to act on.

**A re-run merges instead of refusing.** With the persona and skill already present, the command merges `.pando.toml`, skips those two files, says so on stdout naming `--force` as the way to replace them, and exits `exitOK`. Previously the refusal fired before the write loop, so after a first successful `agent init` the merge path was unreachable and only `--force` — a full overwrite — got past it, which is exactly the re-run a user performs to pick up template changes. `--force` keeps its meaning for all three files.
