Mechanism: `parsePandoTOML` splits the file into text sections. A line counts as a header only at bracket depth 0 — a scanner that ignores brackets inside literal and basic strings keeps a multi-line `Tools = [` from being read as one — and must match `^(\[\[?)([^\[\]]+)(\]\]?)\s*(#.*)?$` with matching bracket counts; anything else fails naming the line. `[[array]]` names keep their marker so an array of tables can never match a table. The four gintrack-owned sections are lifted out as a group and the template's versions spliced back at the anchor, which is what guarantees exactly one of the three auth branches survives. Shared tables merge key by key: absent inserts the template's comment plus key, equal after value normalisation is left, different is left and recorded as a divergence. Nothing is re-serialised; no TOML dependency added.

Tests: `TestAgentInitMergesIntoAnExistingPandoConfig`, `TestAgentInitMergeKeepsEverythingItDoesNotOwn`, `TestAgentInitMergeReportsDivergingKeys`, `TestAgentInitMergeSwapsTheAuthBranch`, `TestAgentInitMergeFailsOnAnUnparsableLine`. `TestAgentInitRefusesToOverwrite` rewritten to cover only the persona and skill files. **Two open questions before this can be marked done. Both are consequences of the acceptance criteria as written, not defects in the code.**

1. *Warn-do-not-overwrite makes the merge a no-op on the `[AGUI]` table of a real Pando config.* Pando dumps every key it knows at its current value, so an existing `[AGUI]` block holds `Enabled = false`, `Path = ''`, `Port = 0` and so on. Those are "present with a different value", so the merge leaves all ten of them and reports them. The user has to act on the report to get an AG-UI listener; the merge alone does not produce a working one. A "a zero value counts as unset" rule would fix it, but applied bluntly it would also write `[MCPServer] StdioEnabled`, which this task's own notes list as a key to warn about.

2. *The merge path is unreachable after a first successful `agent init`.* The persona and skill files then exist, so the refusal fires before the write loop and `.pando.toml` is never merged; only `--force`, which is a full overwrite, gets past it. That is exactly the re-run a user performs to pick up template changes.
