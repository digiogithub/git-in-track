Landed, with a wider seam than the task asked for, because the companion contract of GIT-US-0049 has eight routes and splitting them across waves would have meant changing the interface twice.

`DataProvider` (`web/src/api/provider.ts`) now declares:

```ts
getAgentInfo(options?: AgentRequestOptions): Promise<AguiInfo>;
getAgentHealth(options?: AgentRequestOptions): Promise<AgentHealth>;
runAgent(input: RunAgentInput, options?: AgentRunOptions): AsyncIterable<AguiEvent>;
listAgentThreads(options?: AgentRequestOptions): Promise<AgentThreadSummary[]>;
getAgentThreadMessages(threadId: string, options?: AgentRequestOptions): Promise<AguiMessage[]>;
streamAgentThread(threadId: string, options?: AgentRunOptions): AsyncIterable<AguiEvent>;
deleteAgentThread(threadId: string, options?: AgentRequestOptions): Promise<void>;
cancelAgentRun(threadId: string, options?: AgentRequestOptions): Promise<void>;
```

with `AgentRequestOptions = { repo?: string; signal?: AbortSignal }`, `AgentHealth` and `AgentThreadSummary` declared alongside. AG-UI types are type-only imports from `@pando-ai/sdk/agui/client`, so the boundary gains no runtime dependency.

`runAgent` is an async iterable, not a callback feed, deliberately: it is exactly the shape `PandoThread` consumes, so the SDK's reducer plugs onto the seam with no adapter. (The existing WebSocket events feed is a different animal — a long-lived multiplexed connection — and stays callback-based.)

Also added: capability `Capabilities.agent`, parsed from `features.agent` (docs/07 §capabilities), false in `readOnlyCapabilities` and `companionCapabilities`; and a new `ProviderErrorCode` member `not_supported`, because "this runtime can never do this" is not `read_only`.

Implementations: `companion-provider.ts` (POST `/api/v1/agent/run?repo=`, `Accept: text/event-stream`, the existing bearer header and RFC 7807 mapping, SSE decoded by the SDK's `parseSSE`; `RequestOptions` gained a `signal` and an aborted fetch is re-thrown untouched instead of being reported as an unreachable companion), `browser-provider.ts` (`not_supported` for all eight; the two streams refuse on first pull, not on construction), `fake-provider.ts` (`FakeAgent` script: `turns`/`events`, `info`, `health`, `threads`, `messages`, `reattach`, `runError`, `streamError`+`throwAfter`, plus `agentRuns`/`agentCancels`/`agentDeletes` for assertions).

Tests: `src/api/agent-provider.test.ts` (new, 8), `companion-provider.test.ts` (+7, including a real `ReadableStream` SSE body split mid-frame), `browser-provider.test.ts` (+1).
Reviewer: the `AgentRequestOptions` shape, and whether `not_supported` belongs in the shared error union.
