Implemented in the jj change on top of the Phase 11 stack (not pushed).

**Cache relationship: one source per concern.** The per-machine test-result cache
(`ResultStore`, GIT-US-0115) stays the raw per-test input: the last result of each test.
`<docs>/.pmngr/verify.json` is the per-requirement evidence, and every reader uses it: coverage,
`requirement.stamp` (`spec verify --commit`, MCP `verify_requirement`) and the done transition.
The `verified:` stamp stays the committed baseline. `gintrack spec verify` runs no tests
(GIT-US-0125), so `gintrack spec ingest` writes the cache. After merging the results, every
requirement with a linked test matched by this ingest gets one entry. The entry holds the block
rev now, the commit (or `commits`), the linked tests with their results, the aggregate
`pass`/`fail`/`partial`, the time and `git.authorName`. Each document is versioned. A missing or
corrupt one reads as empty, and the next ingest rebuilds it without an error. Coverage takes the
newest entry of the current block rev and falls back to the stamp when there is none. Because an
entry records the text it tested, fresh results now clear a `text` suspect.

**Core interface.** `core.VerifyCache` has two stores. `FileVerifyCache` is the native store,
over `core.FS`. `MemVerifyCache` is the browser store, which holds the document for the host to
keep as an IndexedDB record. Both are WASM-clean.

**Stamp on done.** The vault installs `FileStore.DoneHook` on every store. The hook reads each
requirement the item implements or modifies from the staged spec, after the delta. It then asks
the coverage host for `StampEvidence` and applies the same `stampDecision` as
`requirement.stamp`. Finally it stages `verified` into the same transaction as the move. The move
is never refused. `specDelta.stamped` and `specDelta.unstamped` report what happened. The
unstamped reasons are those of `requirement.stamp`, plus `missing`, `removed`, `other-project`
and `unavailable`.

**Follow-ups for a human to file:**
- **web/src:** persist `MemVerifyCache` in the `gintrack-cache` IndexedDB. This change did not
  touch web/src. Browser-only mode has no coverage host today, so the cache stays empty there.
- **Existing backlogs:** they need `verify.json` in their `.gitignore`. An upgrade note in the
  CHANGELOG says so.
