**Deviations from the story text, all deliberate and agreed in the wave brief:**
- The routing table is keyed on the **mounted repository id** (`?repo=<id>` against `agent.pando.repos[].repo`), not a project id. An id that names neither a row nor a mounted repository is `agent_repo_unknown` 404; an id that is mounted but has no row uses the section-wide upstream.
- The health probe is `GET /api/v1/agent/health` → upstream `{path}/healthz`, which **does** exist in Pando v0.705.1 (`internal/agui/server.go` `Register`), so the `/info`-as-probe interim of the earlier comment is no longer needed. PANDO-EP-0004 is therefore not blocking.
- Only the **global** in-flight cap (`agent.pando.maxRuns`, default 8) is implemented. There is no per-user cap: the companion has exactly one identity today (its bearer token), so a per-user cap would be the global one under another name. Worth reopening when multi-user identity lands.
- The proxy relays the five extra AG-UI routes one-to-one as well (`/threads`, `/threads/{id}/messages`, `/threads/{id}/stream`, `DELETE /threads/{id}`, `POST /runs/{id}/cancel`), which the story text did not list but the browser SDK needs.

Note the precedence deviation flagged on GIT-T-0009 (env wins here, as docs/07 §3.3 says; the brief's one-liner said otherwise).
