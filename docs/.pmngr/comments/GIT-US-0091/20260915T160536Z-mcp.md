Backend half landed on `feat/phase-9-agent-and-search` (wave 2). GIT-T-0201, GIT-T-0203 and the server-side part of GIT-T-0206 are in_review; **GIT-T-0205 (the card) and the web half of 0206 are a later wave**, so the story stays open.

`internal/server/search_settings.go`:
- `GET /api/v1/search/settings` → backend, configured, mcpUrl, restUrl, projectId, the resolved corpusDir, allowRemote, a **live** `reachable` probe (`null` when nothing is configured, with `reachableError`), `corpora[]` (one per mounted repository: its dir and its last `pandosync.Stats`), `documents`, `lastExport`, `reindex` (the running or last job) and `persisted`.
- `PATCH` follows `gitState.persist` exactly: adopt in process (rebuilds the Pando client and every exporter), then reload → replace → save the file, answering `persisted`. **Neither token is patchable and neither is ever written by this path** — only mcpUrl/restUrl/projectId/corpusDir/allowRemote are, so an env-resolved token can never be copied into the file. No `ConfigPath` → `persisted: false`. A non-loopback URL without allowRemote, an unparseable URL or a relative corpusDir is `invalid_request` (400) with nothing adopted; the URL rule is delegated to `pando.New` so the two cannot drift.
- `POST /api/v1/search/reindex` → 202 `{jobId, startedAt, phase}`, runs in the background on `context.WithoutCancel(request)`, publishes `search.progress` (phases export/code/kb/completed/failed), and is polled through `settings.reindex`. Per repository: `ExportAll` then `IndexProject(repo path)`. Then one KB pass: `ReindexKB` when a REST URL is configured (real scanned/added/updated/deleted counts in `kb`), otherwise `kbNote` says "Re-exported, awaiting Pando's next import pass" — the honest wording the story asks for. The three halves are independent: `exportError` and `codeError` are per repository and a Pando failure never invalidates an export that worked. A second call is `search_reindex_running` (409); nothing configured at all is `search_not_configured` (400).

Tests in `internal/server/search_settings_test.go`: the GET shape and the corpus dir matching `agent init`'s KBPath, the persistence round trip against a real config file, the no-config case, three validation refusals, the happy reindex (export on disk, code job, progress event on the hub), the 409 with the running job unaffected, and the partial failure.

Docs: docs/07 gained "Semantic search settings and reindex" with all three shapes, the `persisted` semantics and the **instance-global embedding-model** warning (Pando skips chunks whose vector length differs, silently, and the model is per instance, so a change degrades recall for every consumer until a full reindex). `search.progress` is registered in docs/07 §5.6; CHANGELOG updated.

For the card (GIT-T-0205): the JSON shapes above are the contract; poll `GET /api/v1/search/settings` or follow `search.progress` for the reindex.
