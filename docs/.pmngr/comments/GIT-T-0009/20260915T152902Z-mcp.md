Landed. `internal/config/config.go` gains `Agent{Enabled, Pando}` and `Search{Pando}`; `internal/config/pando.go` is new and holds the env names, the token accessors and the resolved snapshot; `internal/config/validate.go` gains `validateAgent`/`validateSearch`/`validatePandoURL`; `internal/config/load.go` reads the three env vars; tests in `internal/config/pando_test.go`.

Shape (camelCase YAML, matching the existing file): `agent.enabled`, `agent.pando.{url,path,token,tokenFile,agent,insecureTls,allowRemote,maxRuns,repos[]}` with `repos[].{repo,url,token,tokenFile,agent,insecureTls,allowRemote}`, and `search.pando.{mcpUrl,mcpToken,restUrl,restToken,projectId,corpusDir,allowRemote}`. Defaults: url `http://127.0.0.1:8090`, path `/api/v1/agui`, agent `backlog-assistant`, maxRuns 8, everything else off.

Accessors, so no token is ever copied into a marshalled struct: `Config.ResolvedPandoToken(repoID) (string, TokenSource)`, `Config.ResolvedPandoMCPToken()`, `Config.ResolvedPandoRESTToken()`, and `Config.PandoTargets() PandoTargets` — a snapshot with unexported token fields, `Target(repoID)`, `Token(repoID)`, `Known(repoID)`, `Configured()`, `MaxRuns()`, `Repos()`. Every token field is `json:"-"`, every stanza has a redacting `String()`.

Reviewer, two things to look at:
1. **Precedence deviation from the wave brief.** The brief said "token > tokenFile > env"; this implements **env > token > tokenFile**, which is the documented chain of docs/07 §3.3 and this task's own acceptance criterion ("GINTRACK_PANDO_TOKEN overrides the file token"). Flipping it is a two-line change in `ResolvedPandoToken` if the brief was meant literally.
2. `allowRemote` (default false) is the loopback guard: a non-loopback URL is a validation error without it. The `search.pando` stanza is validated the same way but is otherwise inert — no behaviour consumes it yet, which is the later wave's job (GIT-T-0142).
