Landed in `internal/server/syncengine.go` (new) and `cmd/gintrack/serve.go`: the engine is built in `server.New`, started from `Server.Start` beside the watcher and the tunnel, and stopped with a bounded drain on a detached context beside `s.git.close`. Four flags on `gintrack serve` with `GINTRACK_SYNC_*` env fallbacks, validated before anything listens.

**The registration point is `Server.RegisterSyncHandler(kind, handler)`** in `internal/server/syncengine.go`. It must be called between `server.New` and `Server.Start`, because `Start` replays the journal and a replayed job whose kind has no handler can never run. `Server.SyncEngineHandle()` hands the engine to whoever owns a kind so it can enqueue its own work. Adding `youtrack.import`, the comment push or the KB publish is one line each.

`internal/config` is untouched — it belongs to another agent this wave — so there is no `sync.engine` section: the precedence chain is flag > env > default with no file layer, and `PATCH /api/v1/sync/settings` reports `persisted: false`. Same reason `docs/02-architecture.md` has no paragraph on the engine yet. Both are spelled out on GIT-T-0175, GIT-T-0180 and GIT-T-0184 and in docs/07 §4.1.
