Partially landed; staying **in_progress** because the hub subscription itself belongs to wave 2 (`internal/server` is out of this wave's ownership, and importing it from `internal/pandosync` would be a cycle).

Done in `internal/pandosync/exporter.go` — the exporter side of the contract:
- `Event{Kind, ID, Path}` with kinds `ItemChanged`, `ItemRemoved`, `PageChanged`, `PageRemoved`, `Overflow`. Wave 2 adapts `item.changed` and `file.changed` (`IsKb`) to these; the type is defined here so the dependency points one way.
- `Exporter.Apply(ctx, Event) (Stats, error)` rewrites exactly the one affected file — `TestApplyItemChangedRewritesExactlyOneFile` also asserts an unrelated document keeps its mtime.
- A deleted item or page removes its corpus file; an `ItemChanged` for an item that has already vanished from the index is treated as a removal — `TestApplyRemovals`, `TestApplyItemChangedForAVanishedItemRemovesTheFile`.
- A burst over the same document collapses to one write even with no debounce at the caller, because the content hash absorbs it — `TestApplyBurstOverTheSameItemWritesOnce`. Debouncing the watcher burst is still worth doing in the hub adapter, but correctness no longer depends on it.
- A write failure is returned and does not poison the exporter; the next event over the same document retries — `TestWriteFailureDoesNotPoisonTheExporter`.
- `Overflow` runs a full export — see the note on GIT-US-0073.
- `Apply` and `ExportAll` serialise on one mutex, verified under `-race` with concurrent exports, applies and an overflow in `TestApplyDuringExportAllIsSafe`.

Remaining for wave 2: subscribe to the hub, coalesce per target path over a debounce window, map hub events (and hub overflow) onto `pandosync.Event`, and keep the subscriber goroutine alive across failures.
