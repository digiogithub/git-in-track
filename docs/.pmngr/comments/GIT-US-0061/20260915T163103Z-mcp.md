**What a reviewer should look at**
- `hitl.ts:classifyHitl` — the SDK's `isPermissionRequest`/`isQuestionRequest` narrow on the *name* only, so the argument shape is re-checked here; a half-streamed payload becomes `malformed` and the store refuses it immediately (deny for a permission, `cancelQuestion()` for a question). That is the "malformed argument payload produces a denial" criterion.
- `PermissionDialog.tsx` — Deny is the resting state; Escape / backdrop / the corner close all hold the dialog open and ask, and the confirmation's answer is a denial. Nothing can close without an answer reaching Pando.
- `store.ts:settle()` — the one place that answers without a human. It only ever auto-approves a permission whose *underlying* tool name is in `alwaysAllowed`, and only ever auto-runs a **non-HITL** call. Worth a second pair of eyes.
- **Pando has no per-thread permission policy**: "always allow" is a client-side memory in the store, keyed on the tool name, in memory only, cleared by `attach`/`newThread`/`selectThread`/`dispose`, and shown as a revocable badge under "Standing approvals" in the state panel. Stated plainly in docs/05 §19.7 along with the "HITL is the interim boundary, superseded not replaced by the allow-list" paragraph. **The ADR half of that criterion is not done here** — ADR-035 belongs to W1e's files, which this wave does not own; the coordinator should add the same paragraph there.
