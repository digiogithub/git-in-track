Landed in `internal/vault/youtrack.go` (+ `youtrack_test.go`), with the dispatch cases in `vault.go` and `dispatch.go`. Every acceptance criterion of the story is met; the story is left `in_review` rather than `done` because GIT-T-0060 still owes its documentation half.

**What a host must wire.** `(*vault.Vault).SetYouTrackProvider(func(ctx, project string) (vault.YouTrackSource, vault.YouTrackLink, error))` on each project mount. `*youtrack.Client` already satisfies `YouTrackSource`; `YouTrackLink{BaseURL, Project, FieldMap}` is built from `config.YouTrackLink`. With no provider the two methods answer `unavailable`, which is the browser-only case.

**What a job handler calls.** `Workspace.Dispatch(ctx, "youtrack.import.run", params)` — or the typed `(*Vault).YouTrackImportRun(ctx, vault.YouTrackImportParams{...})` — with `{project, query|ids[], depth (0..5), includeLinks, includeComments, includeAttachments}`. `youtrack.import.preview` takes exactly the same parameters, writes nothing and returns the same action decision. Both are synchronous, take the vault mutex only for the index reads and the writes, and return one `WriteSet` for the whole batch.

**Decisions a reviewer must know.** (1) Ids for new items are allocated before any write, so a parent or link pointing at another issue of the same batch resolves; an issue that then fails to write leaves a gap in the counter, which the id rules allow. (2) The status of an updated item is applied with `MoveWith(Force: true)` — the remote tracker is the authority on the state of an issue it owns. (3) `includeAttachments` records the attachment paths on the item and warns; downloading the binaries belongs to the sync engine. (4) A comment file is rewritten once after `AddComment` to carry its `external` reference, because `core.CommentDraft` has no such field — that reference is what makes a re-import skip the thread. (5) An issue the tracker will not hand over is a per-issue failure, not an aborted batch. (6) A bare query is scoped to the linked YouTrack project, and an import is bounded at 500 issues with a warning.

**Left for the docs owner (GIT-T-0060):** `docs/07-cli-and-api.md` §4 and `CHANGELOG.md` are owned by another agent this wave, so the two methods are not documented there yet. They need: the parameter object above, the plan and result shapes (`YouTrackImportPlanItem`, `YouTrackImportIssueResult`, `YouTrackImportResult`), the `(external.system, external.id)` idempotence rule, and the `unavailable` / `invalid_request` error codes.
