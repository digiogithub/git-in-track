**SDK vs. local**, as the story asks the PR to state. The SDK's `PandoThread` is the reducer, its `parseSSE` the parser, its `applyJsonPatch` the patcher, its `approve`/`deny`/`answerQuestion`/`cancelQuestion`/`isPermissionRequest`/`isQuestionRequest` the HITL answers. Local code is limited to: the provider-backed transport (the SDK client cannot carry `?repo=`, and features do not `fetch`), a three-case supplementary fold for events the SDK's reducer has no branch for (`MESSAGES_SNAPSHOT`, `TEXT_MESSAGE_CHUNK`, `ACTIVITY_SNAPSHOT`), the unapplicable-patch filter (the SDK *throws* where the story says ignore), the `AgentMessage` projection, run status, error mapping, thread-id persistence, the tab guard and the server-side thread calls the SDK documents itself as not making. Details per task in the task comments.

**The seam for the chat wave.**

```ts
type AgentRunStatus = 'idle' | 'running' | 'interrupted' | 'cancelled' | 'error';

type AgentToolCall = {
  id: string; name: string; argsText: string; args: unknown;
  status: 'streaming' | 'pending' | 'done'; result?: string;
};

type AgentMessage = {
  id: string;
  role: AguiRole;           // user | assistant | tool | activity | reasoning | system | developer
  text: string;             // both content shapes flattened
  reasoning?: string;       // a separate channel on the wire; never merged into text
  toolCalls: AgentToolCall[];
  toolCallId?: string;      // on role 'tool'
  activityType?: string;    // on role 'activity'
  error?: string;
};

type AgentError = { code: 'not_supported'|'unauthorized'|'session_busy'|'cancelled'|'transport'|'run_error'|'internal'; message: string };
type AgentInterrupt = { toolCalls: PendingToolCall[] };
```
