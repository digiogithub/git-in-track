Agreed with the previous agent, and closing as covered rather than implementing a second enqueue path. Three reasons, in order of weight:

1. **A `publishWrite` inspection would double-enqueue.** `Vault.autoPushComment` already queues from `comment.add`, after the vault lock is released and with `context.WithoutCancel(ctx)`. `publishWrite` runs on the very same write. Inspecting the `WriteSet` there would queue a second job for every comment — and while the engine now folds them (they share a kind, a key and, since GIT-T-0173, an id), a design whose correctness depends on a downstream deduplicator is not a design.

2. **The guard the task asks for is already there, and is stronger than the one it specifies.** The task wants a changed-field guard so the job's own `external` write-back cannot re-trigger a push. The vault guards on the comment's own `external` reference instead: a comment that already carries a YouTrack id is never queued again. That holds for the write-back *and* for a comment rewritten for any other reason — a body edit, a rebase, a `gintrack item edit` — where a changed-field check would let a second push through.

3. **One decision, one place.** `comment.add` is the single path every surface writes a comment through: REST, the web app, MCP and the CLI. That is what the acceptance criterion "a comment written over REST or from the web app enqueues exactly one push in auto mode and none in manual mode" actually asks for, and it is satisfied — `internal/vault/youtrackpush_test.go` pins both modes and the absence of the feedback loop, and `TestPushCommentsReachesTheVaultLink` (GIT-T-0164) pins the setting reaching the link the vault reads.

What `internal/server` owed has landed under GIT-T-0164: `youtrackLinkOf` now carries `push_comments` into `vault.YouTrackLink` — without which the vault's `auto` branch could never be true — and the enqueuer seam was already installed in `installYouTrackSeamsOn` with `context.WithoutCancel`.

The three acceptance criteria about behaviour are met by that code; the fourth, which names a mechanism this task proposed, is deliberately left unticked rather than ticked against something else.
