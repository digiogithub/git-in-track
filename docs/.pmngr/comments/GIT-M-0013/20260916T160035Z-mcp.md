**Closed 2026-09-16.** Both epics are done and nothing under this milestone is open.

The last blocker was Pando's, not this repository's: an AG-UI run deadlocked on its first `gintrack_*` call because the MCP tool cache bound every tool to the process-wide permission service instead of the caller's. Fixed as `PANDO-US-0031` (commit `38abda0`, PR digiogithub/pando#18), which also closed two defects that rode along — the system-prompt catalog listing poisoning the cache with a throwaway service, which could deadlock every surface including the TUI after any configuration change, and `permission.Request` blocking forever with no context or deadline.

Verified end to end afterwards with the generated configuration untouched: the permission prompt reaches the browser, an approval resumes the run to a correct answer, `AutoApprove` skips the prompt, and the tool allow-list still refuses bash. docs/20 §7 no longer recommends the `mcp_call_tool` workaround and names the minimum Pando build.

Note for whoever picks up the corpus work: branch `feat/pando-indexes-repository-directly` retires the exported corpus in favour of indexing the repository directly, which supersedes part of what GIT-EP-0019 shipped. That is a new direction, not an unfinished criterion of this milestone.
