Web half (GIT-T-0139) is in review, not done, because one acceptance criterion cannot be met against the committed API. The story asks for one row per YouTrack **State / Priority / Type value** mapped onto a local status id; what exists is a **field-name** map: `integrations.youtrack.field_map` is `map[string]string` (git-in-track field → YouTrack custom field name, `internal/config/projectlink.go`), and `GET /api/v1/youtrack/fields` returns `{id, name, type, bundleId, bundleType, canBeEmpty}` with no bundle values. Per-value mapping needs both a value-carrying discovery response (the enum/state/version bundle endpoints) and a nested `field_map` shape, so it is a backend change, not a frontend one.

What landed is `web/src/features/settings/YouTrackFieldMap.tsx`, inside the YouTrack settings card: one native `<select>` per key of `gintrackFields` as the companion declares it, case-insensitive defaults proposed on first open and badged `proposed` (never saved silently), an `unmapped` badge for what nothing matched, a `missing in YouTrack` warning that keeps a mapping the instance no longer offers until it is cleared explicitly, and a save that patches the settings endpoint and reports `persisted`. Vitest covers proposal, unmapped, missing, clear and save; `npm run tokens:check` passes. GIT-T-0131, GIT-T-0136 and GIT-T-0143 were not part of this agent's scope.
