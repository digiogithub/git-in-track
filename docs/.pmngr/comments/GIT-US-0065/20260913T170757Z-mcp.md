Closed. The last thing this story was waiting on was `docs/03-data-model.md` §6, which still described `field_map` as a flat `map[string]string` that "does not translate the values inside them". That paragraph and the `field_map` row of the table have been rewritten to the shape that actually shipped: an entry is either a field name or a `{field, values}` block, the flat form is written back flat, keys are names on both sides rather than ids or localized names, and only `status`, `priority` and `type` accept a value map because those are the fields whose vocabularies differ between the two systems.

The paragraph also now records that `labels`, `due` and `sprint` are refused at load time rather than stored, each with the reason it was never a mapping in the first place.

Verified after the edit: `go build ./...`, `go test -race ./...` and `make lint` are all clean.
