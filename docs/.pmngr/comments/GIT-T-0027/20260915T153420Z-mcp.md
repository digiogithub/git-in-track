**Decision — the transport is the provider, not a `PandoAguiClient`.** Documented at the head of `web/src/features/agent/client.ts`. Two reasons: `PandoAguiClient.agentUrl()` builds `{base}{path}/{agent}` with no room for the `?repo=<id>` the companion needs to pick an upstream (docs/07 §"The agent proxy"), and a client holding its own `fetch` would be a second transport beside `DataProvider` with its own error mapping. So `CompanionProvider.runAgent` POSTs and hands back the SDK's own `parseSSE` output, and `createAgentTransport()` presents that to `PandoThread` as the one method it calls. `asThreadClient()` carries the one unavoidable cast (`PandoThreadOptions.client` is a class type with private fields, so it cannot be matched structurally).
