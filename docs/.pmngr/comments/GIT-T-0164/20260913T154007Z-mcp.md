Left `todo`: `internal/server` and `internal/config` are owned by other agents this wave.

Most of this task is already answered by the vault half that landed, and the server side is now thinner than the description assumed.

`shouldPushComment` no longer belongs in `internal/server` at all: the decision lives in `Vault.autoPushComment` (`internal/vault/youtrackpush.go`), reached from `comment.add` after the vault lock is released. It is true only when an enqueuer is installed, the comment carries no YouTrack reference yet, the parent item carries one, and the project's link says `auto`. Every surface goes through `comment.add`, so there is exactly one decision and no per-surface copy — see GIT-T-0171.

What `internal/server` still owes:

1. Read `integrations.youtrack.push_comments` from `project.yaml` (default `manual`) in `internal/config`, and carry it into the link the provider returns: `vault.YouTrackLink` now has a `PushComments` field, and `vault.YouTrackPushAuto` / `vault.YouTrackPushManual` are the two values.
2. Install `vault.Vault.SetYouTrackEnqueuer` on every mount, wiring `vault.YouTrackJob` onto `syncengine.Request{Kind: job.Kind, Key: job.Key, Payload: json(job.Payload)}` and returning the job id. (`internal/server/youtrackjobs.go` already does this — good.)
3. Log the decision once per item rather than once per comment. The vault does not log; that stays server-side.

A `YouTrackJob.Payload` for `vault.JobKindCommentPush` decodes as `{project, itemId, commentPath}`.
