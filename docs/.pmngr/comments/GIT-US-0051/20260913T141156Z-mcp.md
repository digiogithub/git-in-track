Landed. `CategoryTriage` is the fifth reserved status category; `ItemInbox` (status, snoozed_until,
duplicate_of, source, received, plus preserved unknown keys) is parsed, validated and serialized at
a fixed place in the canonical key order; `Filter.Inbox`/`InboxStatuses`/`SnoozeAsOf` implement the
default exclusion and query-time snooze expiry; `Index.Inbox`, `IsTriage` and `ItemCategory` are the
dedicated inbox surface. Docs: `03-data-model.md` §3.2, §6.1, §6.2, new §6.4 (R-INBOX-1..7), §7.1,
§16, §18; ADR-033 accepted and indexed.

Three things a reviewer must know. (1) **`sprintview.go` was not modified and did not need to be**:
`SummarizeSprint`, `BuildSprintView` and `isSprintCandidate` all consume the cards produced by
`walkCards` in `boardview.go`, so the single `continue` there removes triage from boards, sprint
scopes, sprint candidates and sprint metrics at once, and a sprint naming a triage reference falls
through the existing "no card, no status" branch as unresolved. (2) Two validation rules were added
beyond the brief because they fall out of the same shape: `status: duplicate` with no `duplicate_of`,
and an item that is a duplicate of itself. (3) `make lint` was not run (other agents are mid-edit in
packages it covers); `go build ./...`, `go vet`, `go test -race ./internal/core/...`, `gofmt -l` and
a `GOOS=js GOARCH=wasm` build are all clean.
