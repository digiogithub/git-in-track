Landed in `internal/server/items.go` (`handleSearch` + `mergeSemantic`). Selection is per request: the semantic leg runs only when a backend is installed and the query is non-empty. Exact hits keep the order `Workspace.Search` produced; semantic hits the exact half did not already find are appended, deduplicated by item id (or repository + page path), each tagged `source`. The two lists are concatenated — never re-ranked together — because a Pando fusion score (~0.016) and a core field-weight score are incommensurable. Any failure returns the exact hits with `degraded: true` and the same envelope; `searchState.noteDegraded` logs once per state change (and logs the recovery), and `ErrNotConfigured` is not treated as a degradation. Response: `{"query","hits","total","engine","degraded"}` — the envelope the web wave pinned. Tests: `TestSearchMergesSemanticHitsAfterExactOnes`, `TestSearchDegradesWhenPandoFails` (unreachable / unauthorized / timeout / switched off), `TestSearchRecoversAfterADegradation`, `TestSearchWithoutPandoIsUnchanged`.
